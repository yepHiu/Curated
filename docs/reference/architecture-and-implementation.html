1. 总览

Curated 是本地优先的影片资料库：Vue 3 + TypeScript + Vite 作为 Web 前端，Go 守护进程（curated-backend，入口 cmd/curated）提供 HTTP API、SQLite 持久化、目录扫描、Metatube 刮削、资源缓存与库路径存储在线检测。当前仍以浏览器 + 本地后端为主，同时已有 electron/ 最小桌面壳层：Electron 主进程启动或复用 Go HTTP 后端，等待 /api/health 后在开发态启动或复用 http://127.0.0.1:5173 的 Vite 前端并加载 Web UI；打包态仍加载后端静态托管的 http://127.0.0.1:8081；Electron 对后端请求注入 X-Curated-Client: desktop-electron、版本 header 与桌面 OS header，使后端可在已连接客户端中显示 Curated Desktop 而不是普通 Chrome，并能显示 Windows 11 而不是 Chromium 兼容 UA 中的 Windows NT 10.0；关闭窗口时隐藏到托盘，使后端与 Web 入口继续运行；preload 只暴露 window.javLibrary.pickDirectory()，用于原生目录选择，不承载业务 API。

生产安装包的默认入口已经切换为 Electron：顶层 Curated.exe 是 Electron 桌面壳，Go release 后端位于 resources/app/curated.exe，Electron 以 -mode http 启动自己拥有的后端并加载 http://127.0.0.1:8081。BrowserWindow 的入口 URL 带当前应用版本查询参数；后端对 index.html 与 SPA fallback 返回 no-store，对带哈希的 /assets/* 返回 immutable 长缓存；installer 覆盖升级前删除安装目录内受管理的新旧 frontend-dist，三者共同避免旧 Electron 缓存跨版本继续加载。开发与 release 后端默认都只绑定 loopback；设置页「网络」可把 lanEnabled: true 写入 library-config.cfg（不要求 PIN），完全退出后重新打开会把同端口改绑到 0.0.0.0。主运行时 JSON 的非 loopback httpAddr 仍必须显式设置 lanEnabled: true，否则拒绝启动 HTTP 服务。Host / CORS 校验跟当前真实监听走，保存偏好但尚未改绑时不放宽私网 Host。窗口关闭默认隐藏到托盘，只有托盘退出或系统级 quit 才会停止 Electron 自己 spawn 的后端；attach 到已有后端时不停止该进程。

桌面包的前端资源已按离线运行约束打包：Outfit 字体来自 @fontsource/outfit，浏览器缺少原生 HLS 时按需动态导入官方 npm 轻量构建 hls.js/light。当前后端输出单一的本地 rendition，前端只依赖 light build 保留的 MSE、XHR、事件与 level API，不需要完整版额外的字幕、EME/DRM、alternate audio 或 CMCD 控制器；运行时不依赖 Google Fonts 或 CDN script。

浏览器 → 直连 Go :8080（loopback 开发）或 Vite /api 代理 → SQLite + 文件系统

前端通过环境变量 VITE_USE_WEB_API 在两种数据源间切换：

  • true：本地 loopback 开发态直连开发后端 :8080；release :8081 与其他模式调用同源 /api/...。
  • 非 true：使用内存 Mock 服务，无需后端。

2. 前端（Vue 3 + Vite）

2.1 入口与路由

  • src/main.ts：创建应用、挂载 router、引入全局样式（含 Tailwind v4 / shadcn 主题）。
  • src/App.vue：根组件，通常承载 router-view。
  • src/router/index.ts：使用 Hash 路由（createWebHashHistory），子路由挂在 layouts/AppShell.vue 下：
    • /library、/favorites → 同一 views/LibraryView.vue（通过路由名区分模式）。/recent 与退役的 /tags 重定向到 /library；后者保留 tag 及其他 query。
    • /history → views/HistoryView.vue（观看历史：按本地日期分组；数据见 2.5）。
    • /detail/:id → views/DetailView.vue
    • /player/:id? → views/PlayerView.vue
    • /settings → views/SettingsView.vue
    • /lock - PIN App Lock screen using views/LockView.vue; the router and idle-lock monitor redirect locked Web API sessions here with a redirect query.

2.2 分层：视图 → 组件 → 服务 → API

层级职责典型路径

核心逻辑：src/services/library-service.ts 根据 import.meta.env.VITE_USE_WEB_API === "true" 导出 webLibraryService 或 mockLibraryService。页面与组件只依赖 useLibraryService()，从而与「是否连后端」解耦。

2.3 Web 适配器

src/services/adapters/web/web-library-service.ts 将 UI 需要的操作映射为 src/api/endpoints.ts 中的方法（如 listMovies、getMovie、patchMovie、startScan、getTaskStatus 等），并在适当时合并列表缓存、处理播放地址（见 src/api/playback-url.ts）。

库路径存储状态同样走服务层：Web API 模式通过 GET/POST /api/library/paths/storage-status 刷新 libraryPathStorageStatuses；AppShell.vue 启动时挂载 use-library-storage-status-alerts.ts，把异常路径推送到新的 toast 与通知中心。设置页和导入弹窗根据 canRescan / canImport 阻断对离线或卷不匹配硬盘的操作。

备份维护也保持相同边界：SettingsBackupSection.vue 只调用 service contract；Web adapter 映射到受 PIN 保护的 POST /api/maintenance/backups、/verify 与 /preflight，Mock adapter 明确拒绝真实文件系统操作。页面允许 Electron 目录选择或手工填写后端机器绝对目录，每次生成新的 UTC 时间戳包名；创建成功后再通过 PATCH /api/settings 把目录保存为 backupDirectory，后续刷新或重启从 GET /api/settings 回填。页面不提供在线 restore；真正替换数据库仍只允许在完全退出 Curated 后通过维护 CLI 执行。

Library Health 也只经过 service contract：SettingsLibraryHealthSection.vue 调用受 PIN 保护的 POST /api/library/health/scan、/repairs、GET /repairs/{repairId} 与 /actions，Mock adapter 明确禁用真实诊断/修复。扫描只读并以稳定 finding ID 聚合 SQLite、存储、文件、资源、元数据、孤儿状态和导入暂存；离线根跳过逐文件判断。修复/清理在执行前重新扫描、要求显式确认并持久化 parent/child 或审计证据；最终影片文件不进入清理候选。该工作台从 Settings 动态加载，英文/日文消息也按需加载；2026-07-21 D3 构建的首屏 JS 为 342915 raw / 123382 gzip、全量 JS 为 2107543 / 697307，Library Health 独立 chunk 为 21160 / 4988，仍低于未放宽硬预算。

Saved Views 同样只经过 service contract：LibrarySavedViewsControls.vue 由 library-query.ts 生成版本化白名单筛选与 canonical route；Web adapter 调用五个 /api/library/saved-views CRUD / reorder 端点并以 SQLite library_saved_views（migration 0032）为权威，Mock adapter 使用独立 curated-library-saved-views-v1。可保存字段包含 mode、搜索、实体筛选、tab、播放状态、精确用户评分、分辨率与相对入库窗口；selected/from/browse/back/autoplay/t 不进入持久定义，删除视图不影响任何影片或用户数据。

演员 canonical identity 同样保持 service contract 边界：ActorMergeDialog.vue 只调用 preview/apply 方法；Web adapter 映射到 POST /api/library/actors/merge-preview、POST /api/library/actors/merge 与 GET /api/library/actors/merge-audits，Mock adapter 以 curated-actor-merges-v1 保存 display alias 与 audit。migration 0035 增加 actors.normalized_name、actor_aliases 与 actor_merge_audits，migration 0036 让审计保存当时的 ID/名称快照但不阻塞后续 A→B→C 归并。identity 使用 NFKC、Unicode case folding 和空白折叠；profile、搜索、资料库精确筛选、头像、标签、外链、scraper 与 metadata ingestion 均解析 alias。preview 完全只读且 token 覆盖 profile、影片、标签、外链、alias、推荐反馈和萃取帧 actor JSON；apply 必须显式确认并在单个 SQLite 事务中重新核对、迁移、去重、删除 source、写 audit，失败零部分写入。

Personal Insights 继续遵守同一 service contract：懒加载 /insights 的 PersonalInsightsPage.vue 并行读取一个 overview 与 actor/studio/tag 三个有界 breakdown，并以请求序号拒绝旧范围响应；Web adapter 映射到 GET /api/insights/overview 与 GET /api/insights/breakdown，由 Go/SQLite 对 playback_daily_watch_time、当前进度与本地评分聚合，不返回原始历史。Mock adapter 在服务边界内复用 personal-insights.ts 读取版本化 localStorage。范围固定为 30/90/365/all 和 IANA timezone；completed 表示范围内看过且当前进度达到 90%，评分同样是当前状态。breakdown 使用 canonical actor 和 full-per-entity，跨实体总和可超过 100%；空分母返回 null，UI 显示 —。

路径迁移刻意不进入在线 service contract 或 HTTP API：盘符、挂载点与跨平台根路径变化必须在完全退出 Curated 后使用 path-migrate-plan / path-migrate-apply。plan 只读并输出白名单列影响、样例、目标状态与冲突；apply 先创建并验证备份，再由 internal/pathmigration、internal/maintenance 与 internal/storage/path_migration.go 在单事务中更新、清除旧卷 binding、执行 SQLite 完整性检查并写审计。

src/api/http-client.ts 中 BASE_URL 在本地 loopback Web API 开发态默认直连开发后端 :8080，release :8081 与其他模式默认为同源 /api；也可通过 VITE_API_BASE_URL 覆盖。

src/lib/backend-events.ts 封装 GET /api/events 的 EventSource 连接，并沿用同一套 API base URL 解析与 HTTP-only PIN cookie。use-scan-task-tracker.ts 与 use-library-watch-toasts.ts 会优先消费 task.updated，但仍保留任务状态与 recent tasks 轮询作为断线补偿。

2.4 Mock 适配器

src/services/adapters/mock/mock-library-service.ts 使用内存种子数据模拟列表、详情、扫描任务等。收藏与用户评分等偏好可经 src/lib/mock-movie-prefs-storage.ts 写入 localStorage，刷新后仍保留（与真实后端 SQLite 持久化行为对应，便于离线演示）。

2.5 观看进度与历史（仅浏览器，非 API）

  • src/lib/playback-progress-storage.ts：每条影片的播放位置、时长、更新时间，键名 jav-library-playback-progress-v1。
  • src/lib/playback-watch-time-storage.ts 与 src/lib/playback-watch-time-tracker.ts：播放器按墙钟时间累计有效观看增量；Web API 模式写入 GET/POST /api/playback/watch-time/daily，Mock 模式写入 localStorage 键 curated-playback-watch-time-daily-v1，供设置概览展示 91 天观看时间统计。
  • src/lib/player-route.ts 与 src/lib/navigation-intent.ts：统一构造详情/播放器路由与返回语义；browse= 保存资料库上下文，back= 标记播放器返回目标，?t= 表示续播时间。
  • src/lib/playback-history-groups.ts：历史页按本地日历日分组标题（今天 / 昨天 / …）。
  • src/components/jav-library/PlaybackHistoryCard.vue：历史列表卡片（文案 + 海报 + 底栏进度条）。
  • Web API 模式通过 GET/PUT/DELETE /api/playback/progress 与 SQLite 同步；Mock 模式继续使用 localStorage。锁定启动会先确认认证状态，解锁后才 hydrate。

3. 后端（Go + SQLite）

3.1 进程入口

backend/cmd/curated/main.go 流程概要：

  1. 解析 -config、-mode（http / stdio / both / tray）与可选 -maintenance 备份/恢复或路径迁移动作；离线动作复用正常运行时数据库锁。
  2. config.Load 加载主配置，再 MergeLibrarySettingsFile 合并 config/library-config.cfg（organizeLibrary、metadataMovieProvider、metadataMovieStrategy、defaultImportLibraryPathId、backupDirectory、autoLibraryWatch、autoActorProfileScrape 等）。
  3. 先取得 <databasePath>.runtime.lock 跨进程独占锁，再打开 SQLite：storage.NewSQLiteStore(cfg.DatabasePath)，执行 Migrate，必要时 SeedLibraryPathsIfEmpty。
  4. app.New 组装扫描器、刮削、任务管理器、资源缓存与 internal/storagehealth 存储在线检测器等；启动自动扫描循环 StartAutoScanLoop；若主配置允许目录监听且 autoLibraryWatch 为真，则 EnsureLibraryWatchRunning 启动 internal/librarywatch（fsnotify + 防抖后入队扫描）。若 autoActorProfileScrape 为真，则影片元数据刮削成功后会继续为仍缺头像与简介的演员自动排队 scrape.actor，并启动有界后台补刮循环 StartAutoActorProfileScrapeLoop。
  5. http 模式下 server.ListenAndServe 挂载 backendApp.HTTPHandler()。

3.2 应用对象 App

backend/internal/app/app.go 中的 App 持有：

  • store *storage.SQLiteStore：影片、路径、任务、用户偏好等持久化。
  • library *library.Service：内存种子服务（开发/演示用数据集）。
  • scanner、scraper（Metatube）、assets（缓存下载）、tasks.Manager、storagehealth.Checker 等。

HTTPHandler() 构造 server.Handler，注入上述依赖。

3.3 HTTP 路由层

backend/internal/server/server.go 中 Routes() 注册 REST 风格接口（前缀均为 /api），主要包括：

  • GET /api/health — 健康检查（含 version 构建标识、可选 installerVersion 安装包版本号、channel、databasePath 等）。
  • GET /api/auth/status, POST /api/auth/setup-pin, POST /api/auth/unlock, POST /api/auth/change-pin, POST /api/auth/lock, PATCH /api/auth/settings - PIN App Lock status, setup, unlock, PIN change, current-session lock, and non-secret settings including pinLength for the lock screen cell count. PATCH /api/auth/settings with pinEnabled: false turns PIN off, clears the stored hash, and revokes sessions independently of LAN access. Curated 对本机与 LAN 统一使用全局 PIN 锁；旧 lanRequiresPin 仅保留固定 true 的响应兼容字段。Regular sessions use an idle deadline that is extended by activity; protected API routes return 423 AUTH_LOCKED when PIN is enabled and no valid HTTP-only curated_auth session exists. 无效 setup/unlock 尝试同时按来源 IP 与哈希客户端键计数，五次连续失败后指数退避并返回带 Retry-After 的 429 AUTH_RATE_LIMITED，成功后重置计数。
  • GET /api/auth/sessions、DELETE /api/auth/sessions/{publicId}、POST /api/auth/sessions/revoke-others — 列出和撤销 trusted-forever 会话；迁移为每个会话生成与 cookie token 分离的随机 public_id，API 只返回安全引用、IP/UA/时间和当前设备标识，不暴露 bearer token。
  • GET /api/connected-clients — 当前后端进程生命周期内访问过 Curated 的客户端列表；普通浏览器按 IP + User-Agent 去重，Curated Desktop 额外使用 X-Curated-Client marker 与同 UA 的 Chrome 区分，并使用桌面 OS header 显示 Windows 11；普通浏览器若发送 Sec-CH-UA-Platform-Version 也会用于区分 Windows 版本；最多保留 50 条，返回浏览器 / 系统 / 设备类型、local/remote、first/last seen 与 requestCount；不采集 MAC 地址。
  • GET /api/dev/performance — 开发环境性能摘要（整机 CPU / 后端进程 CPU），供底部性能监测条轮询。
  • POST /api/maintenance/backups、POST /api/maintenance/backups/verify、POST /api/maintenance/backups/preflight — 受现有 PIN 中间件保护的备份创建、包验证与只读恢复预检；严格接受后端机器绝对路径、限制 64 KiB JSON body、创建不覆盖同名文件，并且不暴露在线恢复端点。
  • POST /api/library/health/scan、POST /api/library/health/repairs、GET /api/library/health/repairs/{repairId}、POST /api/library/health/actions — 只读健康报告、持久化有界元数据修复队列和确认式审计清理；执行前重新验证精确 finding，离线存储只做根级报告，重启中断明确落盘。
  • GET/POST /api/library/saved-views、PATCH/DELETE /api/library/saved-views/{savedViewId}、PUT /api/library/saved-views/order — 有序、版本化 Saved Views；最多 50 项、名称规范化唯一、严格筛选 schema、事务化写入与完整重排。
  • GET /api/insights/overview、GET /api/insights/breakdown — 30/90/365/all 本地日历范围的有界个人观看聚合；breakdown 默认 10、最大 25，原始历史不出后端。
  • GET /api/library/movies — 分页列表（query：mode、q、tag、actor、studio、playState、userRating、resolution、addedAfter、limit、offset）；默认按入库时刻新到旧而不按番号；recent 为最近 30 天，未知 mode 返回 400。
  • GET /api/library/movies/{movieId} — 详情。
  • PATCH /api/library/movies/{movieId} — 更新收藏与用户评分（JSON 字段见下文）。
  • GET .../stream — 视频文件流（http.ServeContent，支持 Range）。
  • POST .../scrape — 触发单部影片元数据重刮。
  • DELETE .../{movieId} — 删除影片记录及相关缓存策略由存储层实现。
  • GET/PATCH /api/settings — 设置 DTO（含 organizeLibrary、defaultImportLibraryPathId、backupDirectory、autoLibraryWatch、autoActorProfileScrape、lanEnabled / lanListening / lanAccessUrls、metadataMovieStrategy、元数据源等）。
  • GET /api/library/actors/{name}/asset/avatar — 演员头像同源缓存资源；演员资料刮削成功后会异步下载头像到本地缓存。
  • 2026-09-06 萃取帧：截图任务队列、4K Worker 编码、缩略图回执/重试/撤销、详情原图窗口与 100% 查看、视觉相似人工检查；Web 游标与批量 motion 查询、Mock IndexedDB v2 元数据/原图分离。
  • POST /api/library/movies/{movieId}/frame — 源文件 PNG，20 秒/32 MiB 输出；DELETE /api/tasks/{taskId}/clip — 取消片段。clips 支持 GIF/MP4/WebM，8 个在途/2 个编码任务、2 分钟期限；路径受配置库目录限制。
  • GET /api/curated-frames — 萃取帧分页查询；支持 q、actor、movieId、tag、limit、offset，另支持 cursor/skipTotal；响应带 nextCursor，跳过统计时 total=-1，稳定排序为时间加 ID。
  • GET /api/curated-frames/stats、GET /api/curated-frames/tags、GET /api/curated-frames/actors — 提供萃取帧总数与标签/演员 facet 聚合，前端不再依赖全量列表自行计数。
  • POST /api/curated-frames — 兼容旧 JSON imageBase64 与新 multipart/form-data（metadata + image）上传；入库时生成缩略图 BLOB，不再因同片 3 秒阈值内的近重复帧阻断保存，重复治理改到萃取帧库页面内提示用户复核并删除多余项。
  • GET /api/curated-frames/{id}/image、GET /api/curated-frames/{id}/thumbnail — 分别提供原图与缩略图；历史行缺少缩略图时可回退原图。
  • GET /api/curated-frames/{id}/motion — 提供与萃取帧关联、保存在应用受控媒体目录中的 GIF 动态资源；元数据由 migration 0037_curated_frame_motion.sql 持久化，删除萃取帧时联动删除文件。
  • POST /api/curated-frames/export — WebP EXIF 与 PNG iTXt 导出元数据统一补齐 tags、schemaVersion、exportedAt、appName、appVersion；GET/PATCH /api/settings 通过 curatedFrameExportFormat 与 curatedFrameExportMode 保存通用导出默认格式和原始/带水印样式，显式导出入口仍可覆盖默认样式。
  • POST/PATCH/DELETE /api/library/paths — 库路径 CRUD。
  • GET /api/library/paths/storage-status、POST /api/library/paths/storage-status/check、POST /api/library/paths/{id}/storage-binding/rebind — 库路径背后硬盘的在线/离线、卷不匹配、路径缺失和权限状态检测；Windows 优先支持卷身份，macOS/Linux 作为后续适配项。
  • POST /api/import/movies/code-check — 导入前按文件名解析番号，返回活动库中的 exact / similar 匹配；对话框选完文件后自动调用，并在同一列表旁标注已导入，不另开窗口。
  • POST /api/import/movies — 将浏览器上传的影片文件复制到设置中的默认库路径，并返回 import.movies 任务。
  • /api/import/movies/uploads — 大文件导入的分块续传端点：POST 创建 SQLite-backed session，PUT .../chunks/{chunkIndex} 按 offset 写入并同步 .curated-import 暂存文件后记录 chunk 范围，前端对 retryable 的网络/超时失败会重试同一块，GET 查询状态与恢复诊断，POST .../commit 以不覆盖已有文件的方式提交并触发扫描，DELETE 持久化取消终态并审计清理暂存。后端重启可恢复上传中或提交中的 session 与原任务；目标盘离线时保留会话等待重新协调。
  • POST /api/scans、GET /api/tasks/recent、GET /api/tasks/{taskId}、GET /api/events — 扫描、任务状态与 SSE 任务事件流。

HTTP 中间层对 Host 与浏览器 Origin 做安全校验：默认允许同源与 loopback 开发 Origin，额外跨域入口必须精确写入主运行时配置 corsAllowedOrigins；任意 Origin 回显与通配符 credentialed CORS 已禁用，非法 Host / Origin 返回 403 COMMON_FORBIDDEN。

3.4 SQLite 与内存回退（重要）

列表与详情在 HTTP 层采用「数据库优先 + 空则回退内存库」策略（便于 DB 尚无数据时 UI 仍有演示数据）：

  • 列表：先 store.ListMovies；若 result.Total == 0，再调用 library.ListMovies。
  • 详情：先 store.GetMovieDetail；若 sql.ErrNoRows，再 library.GetMovie。
  • PATCH：先 store.PatchMovieUserPrefs；若返回「影片不存在于 DB 的可 PATCH 集合」且内存库存在该片，则 library.PatchMovie。

注意：GET .../stream 仅走 SQLite（打开磁盘上的视频文件），不走内存种子库；真实播放依赖扫描入库后的文件路径。

3.5 扫描、刮削与任务

扫描由 App 协调：scanner 遍历配置的库路径，解析番号、写库；若开启整理（organizeLibrary），会按规则移动/组织文件。导入影片通过 POST /api/import/movies 将浏览器上传文件复制到 defaultImportLibraryPathId 指向的库根；大文件可走 /api/import/movies/uploads 分块续传，上传中字节暂存在目标库根下的 .curated-import/<uploadId>。0029_movie_import_upload_sessions.sql、movie_import_upload_repository.go 与 movie_import_upload_runtime.go 持久化 session/file/chunk 范围、文件提交 marker、到期时间、诊断和清理审计；chunk 先完成 Sync/Close 再事务记录，启动时从 chunk 行重算计数并恢复原 import.movies 任务。committing 中断可通过 staging/final 状态继续协调，冲突目标永不覆盖；目标盘离线时返回 recoveryStatus=unavailable 并延迟清理。janitor 只处理登记的终态/过期 staging 和严格命名的旧孤立目录，先写审计且永不删除最终文件。复制或 commit 成功/部分成功后触发受限扫描；复制进度、冲突与失败明细通过 import.movies 任务元数据展示。存储在线检测会在启动、手动检查、扫描或导入前探测库路径背后的卷；若外置硬盘离线、路径缺失或卷身份不匹配，前端会通过 toast/通知中心提醒，并阻断对应扫描或导入，避免把离线盘误判为路径删除。刮削通过 Metatube SDK 拉取元数据，assets 可把封面、预览图、演员头像等缓存到 cacheDir；预览图本地缺失时，后端还会基于保存的 source_url / referer_url 做同源兜底转发。长时间操作通过 tasks.Manager 生成 taskId 并发布非阻塞 task.updated 事件；GET /api/events 将事件编码为 SSE，前端优先用它驱动扫描进度和目录监听 toast，同时继续保留 GET /api/tasks/{taskId} 与 GET /api/tasks/recent 轮询 fallback。任务和 provider 健康结果会带 errorCategory 等机器可读诊断字段。另：fsnotify 路径下扫描任务元数据常带 trigger: fsnotify，由 autoLibraryWatch 与主配置 libraryWatchEnabled 共同决定是否启用监听；若 autoActorProfileScrape 打开，则电影元数据保存后还会为头像与简介都缺失的演员自动排队 scrape.actor。

5.4 播放与续播

2026-09-06 播放修复：播放器先请求 descriptor，指定 startPositionSec 在首次会话启动前生效。HLS 按 sessionId 独立管理，同片多端不会抢占；默认 2 个并发准备、8 个保留会话，排队与启动共用 24 秒可取消期限。显式 direct 返回原文件地址。换流在新媒体数据就绪后释放旧流，失败可回退；离开页面取消在途请求并回收迟到会话。

媒体预热不再重复下载 init/分片；起播按当前位置之后的实际连续缓冲和倍速判断，seek 按编码速度决定最多 4 秒追赶。HLS 网络/媒体错误有界恢复，失效会话按当前位置重建。FFmpeg 使用进程级暂停/恢复并保留 readrate 回退，Windows 会解析 Scoop shim 到真实子进程；长 event 清单仍保留历史分片，按需 VOD 与磁盘字节配额尚未实现。

本机播放器拉起（前端）：播放器页不再默认依赖后端 native-play 去执行外部程序，而是由浏览器侧按协议模板拉起本机播放器。当前实现默认以 PotPlayer 为主，协议模板建议值为 potplayer:{url}，并保存在浏览器 localStorage（键名 curated-native-player-browser-template-v1）中，便于按机器区分是否安装了对应播放器。
