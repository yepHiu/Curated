# 写真与漫画 AI 标题整理

用户确认：先预览并确认，可批量应用。

## 范围

复用现有 AI Provider、权限、用量和独立 Action 确认网关。从原始标题、源文件名提取主标题并翻译；漫画区分作者与社团，写真区分模特与摄影师。名字保留原文并附可核对的标题片段；缺失或角色不明确时不猜测，展示待核对说明。不会读取图片、识别人脸或联网补全人物身份。

保留源文件和原始标题，确认后只更新展示标题及独立结构化资料。列表、详情与搜索读取新资料。已有个人标签不变。

## 流程（按用户反馈修订）

与影片保持一致：详情页「更多 → AI 整理」、普通列表卡片右键「AI 整理」，或进入「批量管理」勾选作品后点击底部「AI 整理」 → 核对范围并「确认并开始」 → 既有后台整理 worker → 任务中心 AI 整理分类 → 任务详情核对和批量确认。每任务 1–600 本；页面离开不会取消后台任务。识别只保存提案，不写作品资料。普通列表工具栏不提供 AI 整理；批量模式未选作品时按钮禁用，只提交明确选中的作品，不默认提交当前筛选结果。

识别完成后任务进入「待确认」，计入「需要处理」。任务详情按 25 本分页，展示原值、译名、原文主标题、角色和证据；用户勾选后应用或忽略。批量仅处理明确选中的当前页提案，逐项报告结果。取消停止尚未生成的条目，已生成提案保留；重试只恢复未完成、失败或冲突项，已应用和已忽略项不再生成。

提案、来源快照、版本及状态保存到 SQLite，关闭页面或重启 Server 后可以继续确认。确认请求绑定 bookId 与 revision；后端从持久提案重新取得网关确认票据，立即通过既有确认链路应用，不再调用模型，也不依赖识别时的十分钟票据。原资料发生变化时拒绝写入，标记冲突，重试重新识别。资料、确认回执、任务条目已应用状态在同一事务提交；重复确认不会覆盖后续人工修改。

- Mock 立即产生明确标记的模拟提案并存入 localStorage，支持刷新、冲突与确认；不调用真实 AI。

## 真实识别失败修复（2026-10-17）

- 现场两个写真任务共 5 个条目识别失败。AI 用量证明模型已返回结果；对其中一条只生成预览的复现返回 `roles do not match book kind`，原界面将所有识别错误归因于设置，无法区分原因。
- 提示词按漫画/写真分别渲染角色规则，禁止模型因文件名推翻库类型，也禁止把不适用角色直接映射成模特/作者。疑似错库的信息留在 uncertainty，保留标题整理能力。
- 格式、角色、证据校验失败最多补充一次纠正请求；再次失败保持失败，不绕过验证、不回写资料。Provider 失败不自动纠正；取消/超时保留原期限。提示词审计版本 book-metadata-v2，新增独立 TXT 纠正规则。
- 持久任务 reason 与详情文案区分模型结果不合规、模型连接失败、输出截断；旧通用错误提示改为重试，避免误导用户更改有效配置。
- 新增回归覆盖写真角色纠正、Markdown JSON 纠正、重复不合规/伪造证据拒绝、Provider/截断不纠正、失败原因持久化，以及识别全程不修改作品资料。前端结果提示 7 项测试通过；后端定向书库/模板测试通过，lint、类型检查与 Web API 构建通过。
- 已重新编译并重启开发后端。两条历史失败任务（1 本 + 4 本）均已通过原任务 retry 接口重试。真实模型全部成功，任务中心接口返回待确认 1/4 本、失败 0、已应用 0；使用 book-metadata-v2，提案未应用。

- 最终后端回归：`go test ./internal/app ./internal/agent/prompts ./internal/storage ./internal/server` 全部通过，`go vet ./internal/app ./internal/agent/prompts` 通过；开发后端健康检查正常。
