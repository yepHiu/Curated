# 写真与漫画 AI 标题整理

用户确认：先预览并确认，可批量应用。

## 范围

复用现有 AI Provider、权限、用量和独立 Action 确认网关。从原始标题、源文件名提取主标题并翻译；漫画区分作者与社团，写真区分模特与摄影师。名字保留原文并附可核对的标题片段；缺失或角色不明确时不猜测，展示待核对说明。不会读取图片、识别人脸或联网补全人物身份。

保留源文件和原始标题，确认后只更新展示标题及独立结构化资料。列表、详情与搜索读取新资料。已有个人标签不变。

## 流程（按用户反馈修订）

与影片保持一致：详情单项或列表当前筛选/已选作品 → 核对范围并「确认并开始」 → 既有后台整理 worker → 任务中心 AI 整理分类 → 任务详情核对和批量确认。每任务 1–600 本；页面离开不会取消后台任务。识别只保存提案，不写作品资料。

识别完成后任务进入「待确认」，计入「需要处理」。任务详情按 25 本分页，展示原值、译名、原文主标题、角色和证据；用户勾选后应用或忽略。批量仅处理明确选中的当前页提案，逐项报告结果。取消停止尚未生成的条目，已生成提案保留；重试只恢复未完成、失败或冲突项，已应用和已忽略项不再生成。

提案、来源快照、版本及状态保存到 SQLite，关闭页面或重启 Server 后可以继续确认。确认请求绑定 bookId 与 revision；后端从持久提案重新取得网关确认票据，立即通过既有确认链路应用，不再调用模型，也不依赖识别时的十分钟票据。原资料发生变化时拒绝写入，标记冲突，重试重新识别。资料、确认回执、任务条目已应用状态在同一事务提交；重复确认不会覆盖后续人工修改。

## 实现

- 迁移 0068 保留两库 metadata_json；新增 0069 保存整理任务及逐项提案，无 library-config 变化。
- 调度复用 tag organization worker 的启动、唤醒、取消和重启恢复。识别继续使用 recognize_book_metadata Action、现有 Provider、权限及用量统计。
- 新增 POST /api/ai/book-organizations；GET /{jobId}/items；POST /{jobId}/cancel、retry、review。写端点仅本机管理。review 接受 bookId、revision 和 apply/discard。
- 任务中心使用 book-organize:id 键，kind 仍为 organize；共用汇总、筛选、轮询、状态徽章、详情与取消/重试操作。
- 删除前台分组生成 composable，入口只负责提交。任务详情嵌入结果确认组件；三语文案同步。
- Mock 立即产生明确标记的模拟提案并存入 localStorage，支持刷新、冲突与确认；不调用真实 AI。
