# Curated 带水印截取帧导出 PRD

日期：2026-08-08  
状态：Implemented（首版），视觉方案已确认；保留 EXIF/iTXt 元数据为后续增强项  
范围：Curated「萃取帧」图片导出体验；本文件是需求理解与设计对齐稿，不代表已经进入实现

## 1. 一句话定义

在现有截取帧导出的基础上，增加一种“带水印导出”方式：保持上方截取帧主体不变，在图片下方追加一个使用 Curated 主题背景色的小底框。底框左侧展示品牌标识，右侧展示番号、影片标题和演员信息，最终生成一张适合网络分享的完整图片。

## 2. 背景与问题

Curated 当前已经支持截取帧导出。现有导出结果更像“原始图片文件”，适合个人保存，但用于社交平台或聊天分享时，接收者缺少影片上下文，品牌识别也不明显。用户希望借鉴照片分享中常见的“照片 + 相机信息底框”形式，在不覆盖画面内容的前提下补充来源信息，并让导出图片具有 Curated 的品牌辨识度。

这不是在原图上覆盖半透明文字的传统角标水印，而是一次非破坏性的画布扩展：原始截取帧位于上方，信息底框位于下方。

## 3. 当前实现事实

以下内容来自当前代码，属于“已实现”而不是本需求的目标设计：

- Curated 的「萃取帧」页面支持单帧导出和批量导出。
- 批量导出当前最多选择 20 帧；按演员分组导出时有演员一致性约束。
- 当前导出格式包括 JPG、WebP、PNG，格式偏好已存在于设置中。
- 导出接口目前以帧 ID、可选演员名和格式为主要输入；导出完成后在浏览器端触发下载。
- 每个截取帧已有番号 `code`、影片标题 `title`、演员数组 `actors`、帧图像以及时间等字段。
- Mock 模式与 Web API 模式的截取帧数据边界不同；本 PRD 不预设必须新增后端端点。

## 4. 产品目标

### 4.1 目标

1. 让用户可以明确选择“原始导出”或“带水印导出”，不破坏当前导出习惯。
2. 生成一张上下结构完整、信息层级清楚、适合分享的图片。
3. 用品牌区和主题色建立 Curated 的轻量品牌识别，而不是让水印抢走画面主体。
4. 让番号、影片标题和演员信息在常见图片查看器中无需额外打开详情即可阅读。
5. 对缺失、过长、多演员等真实数据提供稳定的降级规则。

### 4.2 非目标（首版不做）

- 不在原始截取帧上直接绘制遮挡式角标或重复平铺水印。
- 不修改原始帧文件、数据库中的帧图像或影片元数据。
- 不在首版提供复杂的模板市场、自由拖拽排版、字体编辑器或多品牌方案。
- 不在首版自动添加来源网址、抓取站点名称、播放时间、收藏状态、用户评分等未提出的信息。
- 不把带水印结果作为新的“截取帧”回写到 Curated 资料库；它是导出产物。
- 不因为加入底框而改变上方截取帧的裁剪范围、画面比例或清晰度目标。

## 5. 用户与使用场景

### 5.1 目标用户

已经在 Curated 中保存截取帧，并会把图片发到聊天、论坛、社交平台或个人笔记中的用户。

### 5.2 核心场景

**单帧分享**：用户在帧详情或右键菜单点击导出，选择带水印，下载一张包含影片上下文的图片。

**批量分享**：用户在批量管理中选择多帧，选择带水印后导出；每一帧都拥有自己的番号、标题和演员信息，ZIP 行为与当前批量导出保持一致。

**不同主题下分享**：用户在浅色或深色主题下导出，底框采用当前主题语义色，文字和图标保持足够对比度。

## 6. 核心体验与用户流程

推荐的首版流程如下：

1. 用户进入现有的帧导出入口。
2. 在“导出方式”中选择“原始图片”或“带水印图片”。
3. 若选择带水印，界面展示一张低保真预览（可在确认后作为实现阶段的 UI 选项；若首版不做实时预览，则至少展示结构示意和示例文本）。
4. 用户确认导出。
5. 系统为每一帧生成带底框的图片；单帧直接下载，批量按现有规则下载单文件或 ZIP。
6. 成功后提示导出数量；失败时在当前入口附近给出可理解且可重试的错误信息。

原始导出应继续可用，并且首版默认建议保持原始导出，以避免升级后静默改变用户已有的下载结果。是否记忆用户上次选择，列为待确认项。

## 7. 输出图片构图规范（需求级）

### 7.1 整体结构

```text
┌────────────────────────────────────────────┐
│                                            │
│          上方：原始截取帧                  │
│       （尺寸、比例、画面内容保持不变）     │
│                                            │
├────────────────────────────────────────────┤
│  [Curated icon] Curated   ABC-123  标题    │
│                            演员 A · 演员 B  │
└────────────────────────────────────────────┘
```

这张示意图仅用于对齐信息关系，不是最终像素规格。底框应当是图片的完整下边界，不覆盖上方画面；上方与底框之间不额外插入装饰性海报、渐变或大面积留白。

### 7.2 底框背景色

- 底框使用 Curated 的主题背景语义色，而不是业务组件中写死的十六进制颜色。
- 浅色主题与深色主题都必须可读；导出时应明确“采用当前主题”还是“采用固定品牌底色”，这是首轮评审需要确认的关键选择。
- 底框不使用高噪声纹理、强渐变或会干扰文字阅读的背景图。
- 品牌区和信息区可使用极弱的透明度、边界或分隔线区分，但不应出现卡片套卡片的复杂层级。

### 7.3 左侧品牌区

- 放置 About 区域使用的无背景品牌图标（Sparkles）与产品标题，形成一个紧凑的品牌锁定单元。
- 默认文案建议为 `Curated`；是否使用 `Curated Frames` 或本地化产品名，待确认。
- Icon 使用仓库已有的 About 品牌图标样式，不使用带底色的 PNG 方块，不重新绘制、不使用 emoji、不拉伸变形。
- 品牌区只承担识别职责，不放导出日期、版本号或宣传口号。
- 在横向底框中，品牌区应拥有稳定的最小宽度；在窄图宽度下允许缩小或转为上下排列，但不能挤压到右侧主信息不可读。

### 7.4 右侧信息区

右侧按以下层级排列，并整体右对齐：

1. **主信息行**：番号与影片标题在同一行，字号稍大、字重稍重。番号应可被快速识别，标题允许占据剩余空间，整行靠右对齐。
2. **演员信息行**：演员信息使用较小字号和较轻字重，作为辅助信息，与主信息形成明确层级，并与主信息的右边界对齐。

建议的视觉层级（最终数值在 HTML 对齐稿和实现阶段确定）：

| 层级 | 内容 | 视觉建议 |
| --- | --- | --- |
| 品牌 | About 风格的无背景 Sparkles icon + Curated | 中等字号、半粗或品牌字重，左侧保持独立品牌区 |
| 主信息 | 番号 + 标题 | 相对底框正文放大一级，`font-medium` 至 `font-semibold` |
| 辅助信息 | 演员列表 | 小一级字号，`font-normal` 或 `font-medium`，使用次要前景色 |

### 7.5 文案与缺失值

- 番号和标题都存在时，使用“番号 · 标题”或“番号  标题”的紧凑组合；分隔符由视觉稿确认。
- 番号缺失时不显示多余分隔符；标题缺失时可显示本地化的“未命名影片”或保留空白，待确认。
- 演员为空时隐藏演员行，不显示“演员：”空标签。
- 多位演员默认使用可读的分隔符连接；不把数组序列化为 JSON。
- 超长标题和演员列表优先换行；若为了保持底框高度必须截断，应提供省略号，并确保原始导出仍可获取完整信息。
- 不把用户可编辑的标签、备注或外部来源描述混入演员行，除非后续需求明确扩展字段。

### 7.6 尺寸与清晰度原则

- 输出宽度与上方截取帧宽度一致；底框横向铺满同一画布。
- 上方截取帧的像素尺寸和清晰度不因加底框而被二次缩小；若格式编码需要重采样，应在实现方案中明确质量策略。
- 底框高度应由内容和预设比例决定，保证在手机缩略图、聊天预览和桌面查看器中仍能辨识主信息。
- 底框文字不应小到在常见分享尺寸下无法阅读；同时避免底框高度大于主体画面高度的明显失衡。
- 当前 HTML 对齐稿先按“底框约占主体高度 10%”进行压缩示意；最终像素、字号、内边距、品牌区占比和最小画布宽度仍待 HTML 低保真稿评审后确定。

## 8. 导出行为要求

### 8.1 格式

首版建议沿用当前 JPG、WebP、PNG 三种格式，并让“带水印”只改变画布内容，不改变用户已选择的格式偏好。若某格式在实现上无法保留一致的质量或元数据，必须在方案评审时说明，而不是静默回退。

### 8.2 单帧与批量

- 单帧：生成一张带底框图片并下载。
- 批量：逐帧生成，继续遵守当前批量上限和 ZIP 下载约定。
- 每一帧底框中的元数据必须来自该帧关联影片，而不能复用批次第一帧的信息。
- 按演员分组导出时，演员字段是否显示“全部演员”还是“当前分组演员”，需要产品确认；默认建议显示全部演员，避免导出内容与影片实际演员列表不一致。

### 8.3 文件名与嵌入元数据

- 文件名沿用现有导出命名规则，并可增加稳定的 `-branded` / `-watermarked` 标识，避免用户无法区分两种结果；命名方案待实现阶段确认。
- 不应把演员姓名或标题未经处理地拼进文件名而导致非法字符、过长或隐私泄露。
- 现有 EXIF / iTXt / 导出元数据能力应尽量保留；“带水印”不代表可以丢弃原有导出元数据。

### 8.4 原始数据安全

- 生成过程是纯导出行为，不修改原帧 Blob、IndexedDB、SQLite 或影片元数据。
- 生成失败时不留下半成品记录，也不把带水印图重新写入帧库。
- 浏览器内存、临时 Blob 和批量 ZIP 的释放策略属于实现阶段的技术验收项。

## 9. 交互与可访问性要求

- “原始图片”和“带水印图片”必须是有明确文字标签的互斥选项或等价控件，不能只依赖颜色或图标区分。
- 导出按钮在生成期间进入 busy/disabled 状态，避免重复下载。
- 预览（若提供）必须有明确的替代文本或结构说明；装饰性分隔线和品牌背景不应干扰读屏顺序。
- 颜色使用主题语义 token；文字与底框背景满足 WCAG 对比度要求，浅色和深色主题分别验证。
- 窄屏或底框信息过长时不能产生横向滚动；交互面板中的主要触控目标遵循仓库和 UI/UX 规范的最小尺寸要求。
- 错误提示应包含原因和重试路径，不只写“导出失败”。

## 10. Mock / Web / Desktop 边界

这是导出图像的产品能力，不应因为当前运行模式不同而改变用户理解：

- Mock 模式下应能完成带水印导出，便于离线演示与前端测试。
- Web API 模式下可复用现有导出链路，具体由前端合成、后端合成或混合方式在技术方案阶段决定。
- Electron 桌面模式应继承 Web API 或本地前端导出能力，不额外引入与产品无关的桌面专用模板。
- 原始导出与带水印导出的数据来源、权限和隐私边界应保持一致。

## 11. 验收标准（需求层）

### AC1：结构正确

- 导出的图片由上方原始截取帧和下方底框组成。
- 底框不覆盖、裁剪或改变上方截取帧的画面内容。
- 底框横向与主体对齐，输出图片可被常见图片查看器正常打开。

### AC2：信息正确

- 左侧展示 Curated icon 和约定的品牌标题。
- 右侧主信息行同时展示番号和影片标题，演员信息位于下一层级。
- 每一帧使用自己的番号、标题和演员信息；不得串帧。
- 缺失字段和长文本按照第 7.5 节规则降级。

### AC3：主题与可读性

- 底框颜色跟随已确认的主题策略。
- 浅色、深色主题下主信息和辅助信息均清晰可读。
- 常见窄图宽度下不出现文字溢出、横向滚动或底框失衡。

### AC4：导出兼容性

- 单帧和当前批量导出流程均可选择带水印方式。
- JPG、WebP、PNG 的支持范围和失败提示明确。
- 原始导出仍可用，且不会被带水印选项隐式替换。

### AC5：数据安全与反馈

- 导出不会修改资料库中的原始帧或影片数据。
- 生成中有忙碌状态，成功和失败都有用户可见反馈。
- 失败可重试，且不会下载损坏或不完整的文件。

## 12. 建议的首版范围与后续阶段

### 首版（MVP）

- 增加原始/带水印两种导出方式。
- 固定一种底框布局：左品牌、右影片信息。
- 采用已确认的主题色策略。
- 支持单帧和现有批量导出；不新增模板编辑器。
- 完成缺失字段、超长文本、空演员列表和三种格式的验收。

### 后续候选

- 在导出前提供真实比例的 HTML 预览和可切换示例数据。
- 允许选择 2–3 个官方模板（例如紧凑、宽松、仅品牌）。
- 提供品牌标题、副标题和是否展示演员的轻量设置。
- 提供分享尺寸预设（原尺寸、社交平台推荐宽度等）。
- 为批量导出提供统一的“全部演员/当前演员”策略配置。

## 13. 待确认问题（请优先回复）

1. **品牌标题**：左侧显示 `Curated`、`Curated Frames`，还是其他本地化标题？
2. **底框主题**：跟随用户当前浅色/深色主题，还是固定一个品牌底色以保证跨设备一致？
3. **演员范围**：按影片展示全部演员，还是在“按演员”分组导出时只展示当前演员？
4. **导出入口**：在现有导出按钮旁直接增加“带水印导出”，还是点击后通过菜单/对话框选择？
5. **预览**：首版是否必须在导出前提供真实图片预览，还是先通过静态 HTML 低保真稿确认结构？
6. **底框比例**：当前对齐稿采用约占主体高度 10% 的紧凑比例；是否需要比这个比例更宽松？
7. **本地化**：番号、标题、演员字段是否需要随当前界面语言改变标签或顺序？

## 14. HTML 对齐稿计划（下一步，不是本轮实现）

本轮已制作一个不连接真实导出逻辑的静态 HTML 对齐稿：[带水印截取帧导出 HTML 对齐稿](./2026-08-08-watermarked-frame-export-wireframe.html)。它至少包含：

- 一张示例截取帧；
- 浅色和深色两种底框；
- 短标题、长标题、无演员三种数据状态；
- 左侧品牌区与右侧信息区的比例对照；
- 可快速调整底框高度、字号、内边距和演员行显示策略的 CSS 变量。

HTML 稿只用于确认“底框的认知是否一致”，确认后再决定组件形态、图像合成位置、格式编码和测试拆分。

## 15. 成功指标（上线后观察）

- 带水印导出在所有图片导出中的使用比例。
- 单帧带水印导出的成功率与平均生成耗时。
- 带水印导出失败后重试成功率。
- 用户是否继续使用原始导出（用于确认新能力没有破坏旧流程）。
- 关于文字过小、信息错位、颜色不可读或演员显示不符合预期的反馈数量。

## 16. 结论

本需求的核心不是“加一条水印文字”，而是建立一张可分享的 Curated 品牌图片：上方保留内容本身，下方用克制的主题底框补充品牌和影片上下文。当前建议先确认第 13 节的产品选择，再制作 HTML 低保真对齐稿；在此之前不锁定具体 UI 组件、像素尺寸或前后端合成方案。

## 17. 实施结果（2026-08-08）

- 已在截取帧详情、右键菜单和批量操作栏增加“带水印导出”入口；原始导出入口和 Web API 限制保持不变。
- 带水印图片由前端 Canvas 合成：上方保留原始帧，下方追加约占主体高度 10% 的主题底框；左侧使用 About 风格的 Sparkles + Curated 无背景品牌锁定单元，右侧番号/标题/演员整体右对齐。
- 单帧导出直接下载 JPG、WebP 或 PNG；批量最多 20 帧并在浏览器端生成 ZIP。Mock 和 Web API 模式均支持带水印导出。
- 合成过程只读取帧图像和影片信息，不回写原始帧、IndexedDB、SQLite 或影片元数据。
- 当前 Canvas 合成不会自动继承后端原始导出中的 EXIF/iTXt 元数据；如后续需要保留元数据，应单独增加编码/封装处理。

## 18. 导出样式设置实施结果（2026-08-08）

已在“设置 → 萃取帧”的现有“萃取帧导出图片设置”区域增加“默认导出样式”，采用默认模式选择而不是隐藏导出能力的开关。选项为：

- 原始图片：点击通用“导出”时下载原始截取帧。
- 带水印图片：点击通用“导出”时生成并下载带底框的图片。

详情弹窗、右键菜单和批量操作栏可以继续保留两个明确入口（原始导出 / 带水印导出），设置项只决定通用导出动作的默认模式。这样既能满足“平时默认分享带水印”的习惯，也不会阻止用户偶尔导出原图。

默认值为“原始图片”，避免升级后改变已有下载结果。该偏好与现有导出格式设置一起保存：Web API 模式写入 `library-config.cfg` 并通过 `/api/settings` 同步；Mock 模式保存到浏览器本地设置存储。切换设置后会立即影响单帧和批量的通用导出动作，不改变原始帧数据，也不改变显式的另一种导出入口。
