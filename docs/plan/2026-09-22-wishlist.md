## 1. 核心决策与首版范围

插件职责固定为：识别当前页面的影片番号 → 显示「加入愿望单」→ 向已配置的 Curated 服务发送番号 → 展示成功、重复或失败回执。新增网站只增加番号提取与按钮挂载，不要求适配标题、演员、图片、评分或源站详情数据。

Curated 职责固定为：校验和规范化番号 → 持久化愿望条目并去重 → 查询现有资料库 → 按现有刮削设置补齐资料 → 下载并保存图片 → 海报墙和详情展示 → 后续入库匹配与资源复用。

首版仅有一个愿望单。页面名称「愿望单」，默认筛选「待入库」，侧栏显示待入库数量。包括轻量提交、后台刮削、独立详情、手动完成/恢复、自动关联、图片复用与持久存储。自动下载影片、多清单、站点批量爬取、预告片下载和推送通知不在首版范围。

**确认的范围调整：** 首版不接收插件的元数据对象、图片 URL、图片字节、站点作品 ID、页面 URL、站点 Cookie 或 provider 指令；不提供插件资产上传接口。没有识别出番号时不自动提交，允许在插件中修正或输入番号。删除先前方案中“无番号按来源页面加入”和跨站采集快照合并设计。

仅传番号意味着无法保留用户最初浏览的网页，也不能保证封面与该网页一致。详情里的来源为 Curated 实际使用的刮削来源；首版接受这个取舍，不暗中添加 sourceUrl 字段。

## 3. 最小插件协议

拟新增外部入口：`POST /api/integrations/wishlist/items`。

唯一业务字段：

```json
{"code":"SSIS-001"}
```

Authorization 等连接信息放请求头，由公共客户端处理；不要求插件提交 schemaVersion、请求 UUID、站点类型或任务参数。现有 `X-Curated-Client` 和版本标记可保留，仅用于兼容和诊断。首版不暴露通用刮削代理接口。

- 服务端校验非空、长度和支持的番号格式，统一规范化；保留原文。格式有效不代表一定查到元数据。
- 同一规范番号以唯一约束和事务去重，重复 POST 返回同一个条目，不重复创建任务。对“加入集合”操作使用业务身份幂等即可，首版无需额外幂等回执表。
- 新建返回 201，已存在返回 200；条目及待处理工作已提交后才返回。响应保持紧凑，例如 `id`、`result: created|existing|in_library`。结果不承诺刮削已完成。
- 输入错误返回 400；鉴权和服务错误沿用正式错误封装。网络超时可以重发相同番号；429/暂时失败按退避重试。
- 已完成条目重复提交不自动恢复，需在 Curated 明确「重新加入」；重复添加不重置首次加入时间，不强制重刮。
- 插件成功提示为「已加入愿望单」；Curated 中负责展示资料处理中/待重试等细节，插件不轮询刮削阶段。

Curated 内部管理 API 草案：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/wishlist/items` | 分页、搜索和状态筛选，返回列表所需缩略图和少量字段 |
| `GET /api/wishlist/items/{id}` | 详情、补全状态、刮削来源和库中关联 |
| `PATCH /api/wishlist/items/{id}` | 完成/恢复、用户备注或番号修正；并发冲突返回 409 |
| `POST /api/wishlist/items/{id}/refresh` | 重试资料补全/缺失图片，服务端合并重复任务 |
| `PUT /api/wishlist/items/{id}/library-links` | 人工确认真实影片关联 |
| `DELETE /api/wishlist/items/{id}` | 删除愿望，不删除库中影片 |
| `GET /api/wishlist/items/{id}/assets/{assetId}` | 受应用鉴权保护的本地图片 |

### 3.1 连接权限

插件配对后获得可撤销、只允许提交番号的凭证，服务端仅保存哈希。管理清单与访问资料库仍使用现有应用权限；不把 integration 路由整体设为公共接口。拟支持显式配对后在应用锁定时提交，配对界面须说明此权限；回执仅含提交结果，不泄露库中详情。

扩展后台保管凭证并发送请求，内容脚本仅传番号。按实际扩展请求 Origin 行为做精确兼容，保留 Host 校验，不以开放全站 CORS 代替鉴权。请求来源、类型和字段需校验，网络目的地固定为已配置的 Curated。

## 4. Curated 后台资料补全

新增 wishlist enrichment 编排，复用现有刮削 provider、策略、代理、超时和并发控制，业务写入保持独立。首版不为愿望单建立第二套刮削源设置。

1. 番号合法后先保存条目与待处理工作，海报墙立即可见番号和占位图。
2. 优先查询现有库中精确匹配记录；已有完整资料和可用图片时直接复用，不为愿望单无条件再抓一次。
3. 无可用资料时调用现有刮削服务，按当前 provider 顺序查询。
4. 校验候选番号与请求一致。仅标题相似、后缀版本不明或多候选时进入待确认，不自动用第一条搜索结果填充；必要时给查询层增加候选筛选能力。
5. 保存元数据、刮削来源与图片待处理项，再逐图下载；缩略图/封面优先，其后保存 provider 返回的有界预览图集合，不下载预览视频。
6. 生成海报墙专用小图。详情按需加载大图，列表不下载原尺寸预览图。

条目生命周期与资料处理状态分开。资料状态建议 queued/running/ready/partial/failed/needs_review；「待入库」不会因刮削完成变成「已入库」。失败时保留番号和已经成功取得的资料，展示可重试原因；格式修正冲突时提示合并/选择现有条目。

任务必须持久恢复，不能只启动 goroutine 后立即忘记。与现有任务调度共享并发预算和取消规则；退避有上限，进程重启可恢复未完成工作。删除条目或修正番号后，旧版本任务不得回写；短暂联网失败不丢愿望，空结果不覆盖已有有效资料。

愿望单补全不写 movies、影片目录或 NFO，也不因新增愿望触发全库扫描或自动建立库中演员资料。可以提取纯元数据获取能力共用，不能用虚假电影 ID 调用现有资料库持久化流程。

## 5. 独立数据与番号身份

建议最小实体：

- `wishlist_items`：UUID、提交番号、规范身份键（唯一）、元数据及实际刮削 provider/homepage、用户备注、完成信息、处理状态、时间与版本号。
- `wishlist_assets`：条目 ID、角色/顺序、provider 来源 URL、受管理相对路径、内容哈希、尺寸/类型、逐图状态与失败原因。
- `wishlist_movie_links`：条目与真实 movie 的关联、匹配理由和时间；支持错误关联排除。
- 插件凭证：沿专用鉴权模块保存 token 哈希、权限与撤销状态；任务沿现有持久任务能力接入。

不建立浏览站点快照表，不收集多个网页来源。刮削来源由服务器记录在资料里，不能将它描述为用户原先浏览的网站。

服务器作为身份规范化的最终权威，插件仅去除明显空白。复用现有 moviecode 的大小写/分隔符规则及 FC2 处理经验，实施时定义一套搜索、去重和入库一致的规范函数，并覆盖 SSIS-001/ssis001、FC2-PPV 形式及多分卷后缀测试。不同后缀不能直接截断后合并。返回的 provider 别名也须通过已验证规则确认，不能改写请求身份去迁就错误结果。

用户意愿和库中关联分开：有有效影片关联展示「已入库」；没有关联但手动完成展示「已完成」；其余展示「待入库」。再次添加只返回现有状态，不悄悄改变用户意愿。

## 6. 图片保存位置与生命周期

### 6.1 推荐默认位置

**建议新增受管理资产根，默认取最终数据库文件所在目录下的 `assets/`，愿望单使用其 `wishlist/` 子目录。** 先解析数据库绝对路径再构造资产路径，不依赖当前进程工作目录。此为拟议行为，现有程序尚未创建该目录。

| 环境 | 拟议默认图片位置 |
| --- | --- |
| Windows release 默认配置 | `%LOCALAPPDATA%/Curated/data/assets/wishlist/` |
| 本仓库开发态默认配置 | `backend/runtime/assets/wishlist/` |
| 自定义 `CURATED_DATA_DIR`、使用默认数据库位置 | `<CURATED_DATA_DIR>/data/assets/wishlist/` |
| 显式自定义 databasePath | `<实际数据库父目录>/assets/wishlist/` |

建议结构：

```text
<数据库父目录>/
  curated.db
  assets/
    wishlist/
      <wishlist UUID>/
        images/<内容哈希>.<实际格式扩展名>
        derived/<原图哈希>-thumb-v1.webp
```

数据库记录角色、顺序与相对资产路径，目录只保存二进制文件。采用稳定 UUID，修正番号不用迁移目录；文件名由服务器根据内容生成，避免不同来源覆盖同名预览图。相同条目中封面/海报内容一致时共享同一文件。

采用数据库旁目录的理由：遵循现有应用数据位置；无影片目录也能使用；自定义数据库根时资产跟随；便于明确备份/迁移单元；不受安装升级和普通缓存清理影响。`cacheDir` 仍用于可丢弃的临时/派生产物，本功能保存的原图属于持久资产。

首版不增加必须选择磁盘的步骤，不把图片放浏览器 localStorage、安装目录或视频库路径。用户未来需要单独大盘时，可增加 assetsRoot 配置和显式迁移，但首版数据库保存相对路径、业务通过资产存储服务访问，预留这一能力即可。手工只移动数据库不会自动搬图片，文档和迁移工具须明确数据库与资产一起处理。

### 6.2 保存策略

- 默认保存缩略图、封面及刮削返回的受限数量预览图；原图保留，生成适合海报墙的小图。限额与超时集中管理，截断时记录 partial，而不是伪称全部完成。
- 下载通过 Curated 现有代理配置；校验 provider 返回图片地址、重定向、内容类型、文件大小和解码像素。元数据 provider 可以有受信任的自定义配置；不能因此允许图片请求任意访问本机/私网目标。
- 每张图片独立写临时文件，成功校验后原子提交并登记；下载中断不覆盖旧图，磁盘不足时保留条目并报告图片未保存。
- 使用相对路径及受管理根校验；客户端不能指定本地文件名/目录，UI 仅拿受保护的图片 URL。
- 条目标为完成或入库时保留图片；删除愿望才回收其未被本功能引用的文件。派生缩略图可重建，原图不参与普通缓存驱逐。
- 元数据包含的来源 URL 用于重试/溯源，实际本地字节保证原站消失后仍可看。

### 6.3 备份与存储迁移

当前备份 v1 不包含外置图片，不能声称新目录自动被备份。功能完整交付需要补充资产清单、哈希校验和恢复到当前资产根的流程，并验证备份期间下载/删除的并发一致性。若首轮交付暂不扩展备份，必须明确仅覆盖元数据，图片需另行备份，不能标记完整验收。

新增根位置或迁移能力时统一处理数据库与受管理资产；现有只改路径列的离线迁移工具不能被假定会移动新目录文件。部署升级保留资产根，清理只能操作本功能根内的无引用文件。

## 7. 入库联动与复用

双向对账：提交番号时查询已有库；扫描/导入真实影片成功后查询愿望单。`already_indexed`、恢复回收站影片和番号修正等情况也可补关联；不能只处理首次 imported。

自动匹配要求唯一可靠的身份和有效库记录。回收站不算已入库；similar 或多候选需用户选择。扫描/导入事务提交后才建立关联，提供持久待对账或补偿机制，避免“影片已提交、愿望未关联”的崩溃间隙。

入库后默认从待入库隐藏，在已入库筛选仍可回看。删除/回收库中影片后失效关联，未手动完成条目恢复待入库；临时硬盘离线和路径不可读不等于删除。人工排除误匹配后后台不能立即再次关联同一对记录。

资源复用以身份确认在前：

1. 在常规元数据补全/图片下载之前检查愿望单已有资料与有效图片。
2. 资料只补空，保留库中人工修订、已有 NFO 和更可信数据。
3. 图片首版复制到现有影片资产目标并登记 media_assets：开启整理时沿当前影片目录规则，否则沿当前影片缓存规则。目标地址必须由现有影片服务解析。
4. 复制有临时文件和提交顺序保障，失败单独重试、不撤销已成功入库；存在相同有效图片时直接复用。
5. 下载调度跳过已命中资产，不能刚复制完又重抓 cover/thumb；新来源或用户明确刷新时另按刷新语义处理。
6. 愿望单原文件保留，允许首版少量磁盘重复，确保删除愿望不损坏库中封面。未来再按实际容量需要引入共享文件与引用计数。

如果提交时已入库，可显示库中图片，缺失时从本功能补齐。愿望详情应对库中记录被删除有回退：曾仅引用库中图片、尚无独立愿望副本的情况显示可重试占位，不能声称已拥有持久副本。

## 8. 页面与独立详情

拟新增 `/wishlist` 和 `/wishlist/:wishlistId`，在现有 AppShell 中运行。默认待入库，支持已入库、已完成、全部筛选，以及番号/标题/演员搜索、加入时间排序。虚拟化和分页沿现有大列表规则。

| 设计项 | 建议 |
| --- | --- |
| 页面任务 | 海报墙回顾想看的作品；详情辨认作品并处理清单 |
| 层级 | 缩略图 → 番号/短标题 → 处理状态；完整资料在详情 |
| 卡片 | 新 WishlistCard，复用 MediaStill 和网格基础；不附播放进度、双击播放或文件规格 |
| 详情 | 封面、已补齐元数据、预览图、实际刮削来源、备注；没完成刮削也能进入 |
| 主要操作 | 关联时查看库中影片；未关联时完成/恢复；补全失败时重试或修正番号 |
| 状态 | 加载、番号占位、刮削中、部分成功、未找到、待确认、锁定、空列表、网络失败 |
| 交互 | 返回保留筛选和滚动；卡片键盘可达，窄屏主要目标至少 44px |
| 系统影响 | 复用主题与现有 shadcn-vue 基础控件，不引入新全局 token |

「标记完成」可撤销，不等于观看完成；彻底删除另设操作。图片处理失败不阻止浏览其他资料。真实接收番号依赖 Web API 后端；Mock 可演示占位→补全状态，不能伪称支持插件持久写入。

## 9. 插件扩展边界

插件已核实：Manifest V3 + Chrome API；内容脚本→runtime message→background→Curated API 已存在。JAVDB 列表 `extract.ts` 已能提供 code，jable.ts 已有 extractJableCode。两者可以作为首批番号适配入口，无需补完整元数据采集器。

建议每个网站适配器只声明三类能力：是否匹配当前页面、从当前作品位置提取番号、在哪里挂载按钮。页面有多部影片时逐卡片绑定对应番号，不能取页面第一个番号套给所有按钮。动态页面观察和解绑可由公共层协助，站点 DOM 变化只影响本适配器。

公共层负责同一个按钮状态、消息类型 ADD_TO_WISHLIST、API 请求、连接配置、错误反馈。今后适配新站点只增加适配器和所需匹配规则，不变更 Curated 接口或增加 server-side 站点 switch。

扩展性存在两个独立维度：

- 插件能在该网站提取番号，即可提交愿望。
- Curated 当前刮削源是否能查到这个番号，决定资料补全结果；插件支持新站点并不保证刮削源覆盖其所有作品。

识别失败时允许用户输入/修正番号；暂未收录的合法番号仍保留待补全条目。若未来网站使用无通用番号的另一套作品 ID，再按真实需要新增标识类型，不能把随机页面数字硬当番号；首版不预先引入通用 identifier 联合协议。

现有实现入口：`src/content/extract.ts`、`src/content/jable.ts`、`src/utils/messaging.ts`、`src/background/index.ts`、`src/api/curated.ts`。沿用 serverUrl 和 API 基址规范化，避免重复拼接 /api。当前 5 分钟入库查询缓存仅作展示，添加结果以服务端为准。

凭证放扩展本地受限存储，不进入内容脚本可读取的通用 STORAGE_GET/SET。现有 JAVDB 想看清单删除逻辑保留其独立操作语义，新增加入 Curated 愿望单不触发站内删除。

## 20. 详情页播放站点查询（2026-09-24）

### 20.1 站点拒绝自动查询时的呈现

真实网络检查发现当前代理出口访问 Jable、MISSAV 均返回 Cloudflare 403 challenge；服务端无法读取影片详情，因此不能可靠断言收录。403/429 或 challenge 响应现单独返回 blocked，页面显示「站点限制自动查询」和「手动查看」入口，链接到该站点的固定番号详情路径，不标为「已找到」。超时与无法识别的页面仍显示「暂时无法确认」。

### 20.2 跨站查询流程集成可行性（2026-09-24）

用户提供的 Tampermonkey 脚本先从当前影片页提取番号，再用 `GM_xmlhttpRequest` 请求固定站点的详情或搜索地址，解析 HTML 并把结果链接插回页面。其 `@connect` 是用户脚本管理器授予的跨站权限，不是 Curated 网页或 Go 后端天然拥有的能力。脚本中有些 `get` 站点只凭页面结构甚至 HTTP 成功判定存在，`fetchType: false` 则直接给出链接；这些结果不能原样当成“已找到”证据。脚本引入远程 `@require`，产品实现应独立编写适配器，避免运行时依赖第三方脚本更新。

**现有基线**：`backend/internal/server/wishlist_playback.go` 已实现 Jable、MISSAV 两站的固定地址、并行请求、同站 HTTPS 重定向、8 秒超时、2 MiB HTML 上限和精确番号校验；`GET /api/wishlist/items/{id}/playback` 返回 `available / missing / blocked / unknown`，`WishlistPlaybackCard.vue` 只在可确认或受限时提供相应外链。该接口绑定愿望单 ID，资料库普通影片详情尚未复用。现有网络出口对两站均遭遇 403 challenge，因此单纯增加脚本中的站点配置无法解决当前可用性问题。

| 执行位置 | 技术可行性 | 主要限制 | 当前判断 |
| --- | --- | --- | --- |
| Go 后端现有探测器 | 已实现，可供桌面和 Web 共用 | 目标站点可按出口、客户端特征返回挑战页；当前两站实测 blocked | 保留严格判断和手动查看，不把挑战页误报为存在 |
| Curated 网页前端直接 `fetch` 外站 | 一般受浏览器 CORS 限制 | 无法依赖对方开放跨域响应 | 不作为实现路径 |
| Chrome 扩展后台按固定站点查询 | MV3 扩展具备站点权限，技术上可发请求 | 需安装/运行插件；浏览器环境也不保证通过挑战或具备登录态；现有插件仅有愿望单写入链路，尚无查询回传协议 | 适合做用户触发的可用性验证，不能先承诺解决封锁 |
| Electron 主进程或隐藏页面查询 | 可以发起网络请求或加载网页 | 需要管理会话、页面资源与站点变化；普通请求仍可能被挑战 | 暂不引入第二套浏览器运行时 |

**建议路径**：先保持 Jable、MISSAV 两站和现有四态结果。用同一组已知存在、不存在及挑战样本，分别在真实用户浏览器扩展环境和 Curated 后端执行查询，记录 HTTP 状态、是否得到可解析详情、精确番号是否匹配、耗时及错误；不采集或传回站点 Cookie、整页 HTML、媒体地址。每站至少覆盖 10 个已知存在和 10 个已知不存在样本，要求“已找到”零假阳性，挑战/无法判定明确落入 `blocked`/`unknown`。若浏览器端在实际使用环境中能稳定返回可核实页面，再设计**可选**插件查询通道：用户在 Curated 点“检查”后发送限定站点和番号的任务，扩展返回站点、状态、规范页面 URL 与查询时间；后端重新校验番号、站点和 URL，不能把扩展回报作为普通 API 的身份凭证。扩展缺席时仍走现有后端/手动查看路径。

若目标从愿望单扩大到全部资料库影片，可在验证后抽取共用的按番号查询服务，再为普通影片详情增加独立受保护入口和 UI；不要把愿望单 ID 接口套用到影片 ID。扩站逐站增加地址生成、HTML 样本和精确匹配测试；即使详情页番号匹配，也只证明该站提供对应页面，不证明视频当前能播放。界面展示“外站页面链接”，不承诺 Curated 内直接播放。此轮仅完成可行性论证，没有新增请求链路或修改现有产品行为。
