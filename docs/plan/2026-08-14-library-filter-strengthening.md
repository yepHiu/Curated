# 资料库筛选强化

状态：in-progress  
关联需求：REQ-0026

## 问题

现有资料库筛选看起来有 Saved Views，但日常不好用：

- 「我的评分」是精确匹配，选 4 星找不到 4.5 / 5 星。
- 年份、时长、未刮削、无封面、未评分都筛不了。
- 标签 / 演员 / 厂牌只能从别的页面点进去，筛选弹层里改不了。
- 资料库 / 收藏 / 最近入库页几乎看不到当前生效条件，尤其是从详情点进来的标签。
- 排序只有顶栏三枚 tab（入库 / 发售 / 评分），番号、演员、厂商、年份等排不了。

## 本轮落地

不改 Saved Views schemaVersion，只在 v1 上做加法，并修正评分语义。

1. `userRating` 改为最低分（大于等于 N）；新增 `unrated`。
2. 新增 `year`（`YYYY` / `unknown`）、`runtime`（short / standard / long）、`catalog`（unscraped / no-cover）。
3. 筛选弹层用统一触发器打开标签 / 演员 / 厂牌选择板（选项来自资料库 facet；当前 URL 条件不在列表时仍保留可选）。一次只开一块选择板，选择板与筛选卡并排、顶部对齐、间隔 12px。
4. 顶栏在筛选按钮左侧用可关闭芯片展示全部生效条件，与按钮同一行，避免把资料库网格顶下去。
5. 前后端 ListMovies / Saved Views / Mock 客户端筛选对齐。
6. 独立「排序」按钮打开下拉（与筛选弹层分离）；非默认排序时按钮高亮并显示当前排序文案，不在筛选芯片区重复展示。资料库页已去掉左侧「入库时间 / 发售日期 / 评分」三枚 tab，避免与排序按钮重复。
7. 标签筛选改为筛选弹层左侧的独立选择板：与筛选卡顶部对齐、间隔 12px，约 40rem 宽、自适应多列网格（`minmax(11rem, 1fr)`）；已选为可关闭胶囊，用户标签与 INFO 标签分组并列显示库存数量，支持搜索；多个标签为 AND；URL / Saved Views 仍用 `tag` 逗号串，不升 schemaVersion。专门的标签浏览页退役见 [2026-08-16-retire-tags-browse-page.md](2026-08-16-retire-tags-browse-page.md)。
8. 演员 / 厂牌使用同一套左侧选择板（同时只开一块）：演员多选为 AND（须同时出演），厂牌多选为 OR；URL / Saved Views 仍用现有 `actor` / `studio` 逗号串。仅当恰好 1 个 `actor` 时保留演员资料卡。

## 语义

| 字段 | 含义 |
| --- | --- |
| userRating | 本地用户评分大于等于 N，不用刮削分替代 |
| unrated | 没有本地用户评分；与 userRating 互斥，未评分优先 |
| year | 有效发行年；unknown 表示不在 1800-3000 |
| runtime | short 小于 90 分钟；standard 为 90-150；long 大于 150；时长 0 不匹配 |
| catalog=unscraped | 无演员且无元数据标签 |
| catalog=no-cover | 无封面且无缩略图 |
| tag | 逗号分隔；影片必须同时具备全部所选标签，用户标签或 INFO/nfo 标签均可 |
| actor | 逗号分隔；影片必须同时出演全部所选演员（AND，含 alias） |
| studio | 逗号分隔；有效片商命中任一所选厂牌（OR） |
| sort | 网格排序；省略或 `added` 为入库新到旧；`release`/`rating` 与旧 `tab` 查询兼容；`code`/`actor`/`studio` 升序；`year` 新到旧 |

已保存的「正好 4 星」视图会变成「4 星及以上」。这是有意的兼容，比精确匹配更符合个人库用法。

## 明确不做

- 把扫描进度或消息中心搬进筛选。
- 新的 Saved Views schemaVersion。
- 独立升/降序切换（各 sort 键固定方向）。
- 标签浏览页退役已拆到独立方案，不再作为本筛选强化切片的一部分。
