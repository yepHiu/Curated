# 消息中心修复方案

日期：2026-08-14
状态：in-progress
关联需求：REQ-0024、REQ-0025
诊断：[2026-08-14-message-center-product-direction.md](2026-08-14-message-center-product-direction.md)
消息台账：[../prd/message-catalog.md](../prd/message-catalog.md)

本文是修复方案。消息怎么提示由 `docs/prd/message-catalog.csv` 维护；本文件管切片。当前执行入口仍包含刮削治理 REQ-0023，消息中心与它并行但不抢调度实现。

## 要修什么

消息中心现在是 toast 终态的冰箱：复述「扫描完成 / 资料已更新」，不解释系统在干什么，也不替用户判断什么值得打断。红点把成功、失败、运维确认混在一起，入口会被学会忽略。

要把它改成两份工作：

1. **处境感**：打开面板能看出 Curated 现在忙不忙、卡没卡。
2. **分拣**：系统认为用户需要知道的，才留在这里；需要动手的才亮红点。

## 已锁定的产品决定

| 决定 | 选择 |
|---|---|
| 面板结构 | 三块：`现在` / `需要你` / `最近`（最近 = 通知我） |
| 红点 | 只数 `需要你`；打开面板不等于清空需要你 |
| 运维结果 | 家在设置页。消息中心若提及，只做「通知我」，不做「需要你」 |
| 应用更新 | 「通知我」；安装动作留在 Settings → About；侧栏 New 可保留 |
| 存储离线 | 仍是 `需要你`（这是资料库能不能用，不是设置页运维） |
| 持久化 | 本需求不做后端通知表 |
| 进度卡 | 不把 `ScanProgressDock` 搬进下拉框；v1 也不拆除它 |
| 立项 | 单独 PRD（REQ-0024），细化后再实施，不并进 REQ-0023 |

## 运维 vs 通知我 vs 需要你

「运维结果」指用户在设置页主动做的检查、备份、探测、导出，以及那些页面本身已经展示完整结果的状态。它们不该变成顶栏待办。

```
设置页运维 ──────── 结果留在 Settings
                    当场 toast 可以有
                    消息中心默认不写
                    若写，只能进「最近 / 通知我」
                    绝不进「需要你」，不亮红点

资料库运行时 ────── 存储离线、导入冲突、刮削停摆
                    才允许「需要你」
```

### 设置页运维（家在 Settings）

| 事件 | 现在 | 修复后 |
|---|---|---|
| 备份创建 / 验证 / 预检 | toast；不进中心 | 保持：设置页 + toast |
| Library Health 扫描 / 修复队列 | 设置页工作台 | 保持。不要用「去修复」当需要你 |
| Provider ping / ping-all | 设置页健康状态 | 保持 |
| 代理保存 / ping | 设置页 + toast | 保持 |
| 影片 CSV 导出 | toast | 保持 |
| 存储重绑成功 | toast **且写入消息中心** | 改为当场 toast-only |
| 手动检查更新：已是最新 / 出错 | toast | 保持 toast-only |
| 手动检查更新：有新版本 | toast + 消息中心（warning） | 可进「最近」作通知我；不进需要你 |

### 通知我（进「最近」，不亮红点）

库发生了可见变化，或系统想留一句，但用户不必立刻动手：

- 扫描发现 N 部新片
- 后台刮削补全了一批封面 / 资料
- 导入完成（无冲突）
- 有新版本可用（可选跳转 About，跳转 ≠ 待办）
- 健康检查发现 N 项（可选一句「设置里有报告」；不要求去点修复）

打开面板可以把这类标成已读。

### 需要你（红点，直到原因消失或用户明确关掉）

不处理会继续错，或资料库当前不可用：

- 库路径离线 / 卷不匹配 / 路径丢失
- 导入因冲突或目标不可用而失败，且有可处理后果
- 刮削因代理/存储等系统性原因停摆，而不只是单片没刮到

需要你 **不是**「这条消息带了一个 route」。可选跳转可以出现在通知我里。需要你必须是：原因还在，或用户还没处理完。

### 可以沉默（不进消息中心）

- 扫描已开始
- 0 新增的目录监听扫描
- 用户刚点过、页面上已有反馈的成功（复制路径、重绑成功、保存设置）
- 字段校验、Mock 模式提示
- 播放器瞬时回退（除非形成持续不能播）

## 目标形态（v1）

```
┌─────────────────────────────────────────┐
│  消息中心                         清空   │
├─────────────────────────────────────────┤
│  现在                                   │
│  正在刮削 3 / 12 · 队列还剩 9            │
│  （空闲时整块隐藏，不写「系统空闲」）     │
├─────────────────────────────────────────┤
│  需要你                          红点来源 │
│  D: 影片库离线 · 去影片存储              │
├─────────────────────────────────────────┤
│  最近                                   │
│  扫描完成：+8 部新片                     │
│  Curated 1.5.2 可用                      │
└─────────────────────────────────────────┘
```

v1 建议：

- 「现在」只出现在面板内，不在图标旁常驻一行，避免顶栏变运维条。
- 空闲且没有需要你、没有最近时，面板仍可打开，空状态说「没有新消息」，不要假装有系统广播。
- 自动刮削队列属于「现在」。它依赖刮削治理把队列状态变得可归纳；消息中心不自己再造一套任务系统。

## 和现有代码的对应

当前写入点都走 `pushAppToast({ notification })` 或直接 `addNotification`，没有政策层。修复的第一刀是政策，不是新 UI 皮肤。

| 写入点 | 现行层级 | 方案层级 |
|---|---|---|
| `use-scan-task-tracker` 扫描开始 | 未读消息 | 沉默 |
| 手动扫描完成 / 失败 | 未读消息 | 有新增或失败 → 最近；系统失败 → 需要你；0 变化成功 → 沉默或一句最近 |
| 单部刮削终态 | 未读消息 | 成功 → 可沉默或并入最近摘要；失败 → 单片失败进最近，系统性停摆才需要你 |
| 导入终态 | 未读 `system` | 完成 → 最近；冲突/失败 → 需要你 |
| 目录监听扫描 / 刮削 | 未读，易成流水账 | burst 成一条最近 |
| 存储离线 | 未读 `storage` | 需要你，在线后自动消失或降级 |
| 存储重绑成功 | 未读 `storage` | 沉默（当场 toast） |
| `use-app-update` 发现新版本 | 直接写入中心 | 最近 / 通知我 |
| 设置页手动检查更新 | toast + 中心 | 与上同一条，去重 |

「现在」v1 的数据源：已有 SSE `task.updated`、`useScanTaskTracker`、导入任务、以及 REQ-0023 之后可查询的刮削槽位/队列。缺的是归纳，不是新事件管道。

## 切片（细化后才实施）

### M1 政策层（最小可见修复）

不改面板三块布局，先让红点重新变得可信：

- 给写入通知增加层级：`silent` / `notify` / `needs-you`（名字可再定）
- 红点 = needs-you 数量
- 打开面板：notify 已读；needs-you 保持
- 砍掉扫描开始、重绑成功、空成功对未读的占用
- 运维类调用不再传「当待办」的 notification

验收直觉：磁盘都在线、没有导入失败时，顶栏不应因为「扫描完成」「资料已更新」「有新版本」而亮红点。

### M2 「现在」

面板增加活状态块：扫描 / 导入 / 刮削队列的一句摘要。空闲隐藏。不复制进度条。

若刮削队列 API 还没从 REQ-0023 露出，M2 可以先接扫描和导入，刮削队列作为 M2b。

### M3 「最近」摘要

同一波目录监听、同一批刮削终态，合并成一条最近，而不是 N 行。

### M4 「需要你」生命周期

存储离线等以权威状态为准：路径恢复在线后，对应需要你自动清除。用户点 X 可以稍后提醒，但不能靠「打开面板」假装问题消失。

## 明确不做

- 不把所有 toast 补进消息中心
- 不做后端 `notifications` 表、多端同步、系统托盘原生通知
- 不把 Library Health 发现项提升为需要你
- 不在本需求里改刮削调度（那是 REQ-0023）

已拍板并落地：应用更新进「最近」；单片刮削失败进「最近」不刷红点；关掉需要你后本次会话抑制。

## 为何单独开 PRD，以及现在停在哪

2026-05 的通知中心 PRD 假设「toast 的持久化副本」。继续在那份文档上加条目，会把错误模型修成功能。REQ-0023 管刮削并发，消息中心只消费它露出的队列状态，不应绑成同一个需求。

因此 REQ-0024 已进入实现：M1 政策层、M2「现在」（扫描/导入/单部刮削）、M3 目录监听摘要、M4 存储离线自动解除。刮削队列进「现在」仍等 REQ-0023 露出只读状态。消息政策台账是 REQ-0025。

## 细化时还要拍板的点

1. 「最近」空闲时是否保留应用更新那一句，还是完全交给侧栏 New + About。
2. 单片刮削失败：进最近，还是完全靠详情页行内错误。建议最近留系统性摘要，单片失败不刷屏。
3. M2 是否必须等到 REQ-0023 把队列状态做成只读 API。建议 M1 可独立先做。
4. 用户关掉一条「需要你」之后，同一原因是否在本次会话内抑制，还是状态还在就再次出现。建议：会话内抑制，重启或状态变化后可以再出现。
