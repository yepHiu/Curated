- 日期：2026-08-16
- 状态：**已实施**（2026-08-16 用户拍板 Q1/Q2/Q3；同日按实施计划落地，提交 806df1d8 / 4436cba5 / 48f8aa40）
- 后续产出：实施计划见 `2026-08-16-player-progress-frame-markers-plan.md`，UI 稿见 `2026-08-16-player-progress-frame-markers-wireframe.html`
- 类型：前端功能（预计无后端改动 → 实际无后端改动）

## 1. 背景与目标

用户在萃取帧库中已经为影片收藏了带时间戳的萃取帧（例如打了「萃取针」标签的 10 张帧）。目前想跳到这些时刻，必须先进萃取帧库找到对应帧、再经详情跳转进播放器，路径太长。

**目标**：打开影片播放器时，把这部影片已有的萃取帧时刻直接以「标记」的形式画在播放器进度条上；点击标记即可跳转到对应时刻。当多个标记在视觉上过于密集时，合并为一个带数量的标记。

**典型场景**：某影片有 10 张「萃取针」萃取帧 → 播放器进度条上出现 10 个标记（或按密集程度合并成若干个带数量的标记）→ 用户点标记直达。

## 3. 术语

- **标记（marker）**：进度条上代表一个萃取帧时刻的可视元素。
- **合并簇（cluster）**：因视觉密集而被合并展示的一组相邻标记；簇内成员数 ≥ 2 时显示数量。
- **最小间距（min separation）**：两个标记中心像素距离小于该值即判定为密集，默认 12px（可调常量）。

## 4. 功能需求

### FR1 数据加载

- 进入播放器且影片信息就绪后，按当前 `movieId` 一次性拉取该片全部萃取帧（`limit=200`，`total` 超出时分页补拉；单片帧数通常为个位到几十）。
- `totalDurationSec <= 0` 或无片源时不渲染标记层（与进度条禁用条件一致）。
- `positionSec` 越界（< 0 或 > duration）的脏数据直接跳过并 debug 日志，不渲染。

### FR2 标记渲染（样式为开放问题 Q1）

- 每个萃取帧按 `positionSec / duration` 换算为百分比绝对定位在进度条轨道上。
- 标记层叠加在现有 Slider 之上，**层本身 `pointer-events-none`，仅标记元素自身可交互**，不得阻挡拖动进度、悬停预览等既有交互。
- 标记须在沉浸模式 / 全屏 / 窗口缩放下跟随控制栏显隐与伸缩。

### FR3 标记交互

- 单个标记：点击 → `seekToAbsolutePlaybackTime(positionSec)`；悬停显示时间提示（沿用现有时间格式 `formatClock`）。
- 标记为可聚焦元素，`aria-label` 形如「跳转到萃取帧 00:12:34」；触控设备命中区 ≥ 44px（项目既有触控标准）。

### FR4 密集合并（对应原始需求 2a / 2b / 2c）

**判定（2b）——像素级贪心聚类，纯前端：**

1. 通过 `ResizeObserver` 监听 `progressSliderRootRef` 容器宽度 `W`。
2. 每个帧换算像素坐标 `px = positionSec / duration × W`，按时间排序。
3. 贪心分簇：新帧与**当前簇首帧**的像素距离 `< minSeparation（默认 12px）` 则入簇，否则开新簇。以簇首为窗口基准（而非链式比较）保证单簇宽度有界、结果稳定可预测；更长的密集段自然裂为相邻的多个簇，各自带数量。
4. 簇的展示位置 = 簇内成员像素坐标的中点。

**数字展示（2a）：** 簇内成员数 ≥ 2 时，渲染一个稍宽的合并标记并带数量角标（如 `×5`）；成员数 = 1 时渲染普通单帧标记。

**宽度计算（2c）：** 聚类结果是 `(帧列表, duration, W)` 的纯函数，`W` 变化（窗口缩放、全屏切换、侧栏收起）触发重算；首帧测量前 `W=0` 时先按不合并渲染，测量后自动纠正。

**簇交互（开放问题 Q2）**：默认提案为点击簇 → 跳到簇内最早帧，悬停显示簇内时刻的文字提示。

### FR5 实时性

- 播放器内通过既有「萃取」入口新保存帧成功后，立即在进度条上追加对应标记（无需重新拉全量）。
- 在其他页面删除帧导致的标记移除**不在首期范围**（播放器按会话加载数据）。

### FR6 标签维度（开放问题 Q3）

默认提案：不区分标签，标记该片**全部**萃取帧（含「萃取针」场景）。是否需要按标签筛选 / 着色待确认后决定是否纳入首期。

## 5. 非功能需求

- **性能**：单片帧数量级 ≤ 数百，聚类为 O(n log n) 纯函数，宽度变化才重算，无性能风险；禁止逐帧 DOM 监听。
- **测试**：聚类与换算逻辑抽为纯函数放 `src/lib/`（带 `.test.ts`），覆盖：空列表、单帧、密集成簇、跨簇边界、宽度为 0、脏数据跳过；组件层沿用现有 PlayerPage 测试模式。
- **i18n**：新增文案进 `src/i18n`（`zh-CN` 内置，`en` / `ja` 按需加载）。
- **一致性**：Mock 与 Web API 行为一致（统一走 `listCuratedFramesPage`）。
- **提交**：按最小修改单元拆分提交（聚类纯函数 → 标记组件 → 接入播放器 → i18n/测试）。

## 6. 验收标准

1. 打开任意有萃取帧的影片，进度条出现与帧数相符的标记；无帧影片无标记层、无报错。
2. 点击标记精确跳转到该帧时刻；拖动进度、键盘控制、悬停预览不受影响。
3. 构造密集帧（如 1 秒内 5 帧）时合并为 1 个带 `×5` 角标的标记；拖宽窗口后按新宽度重新分簇。
4. 播放中新萃取一帧，标记立即出现。
5. Mock 与 Web API 模式行为一致；聚类纯函数单测通过。
