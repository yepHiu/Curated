## 已确认的改进点

### A1 · 优先：请求失败没有反馈

- 位置：`src/components/jav-library/PlayerPage.vue:2226`。
- `togglePictureInPicture()` 对进入、退出异常统一静默吞掉。
- 用户点击后遇到媒体未就绪、权限/策略限制或不支持的媒体时，无法知道为什么没打开，也没有重试指引。
- 组件探针模拟 `InvalidStateError`，确认接口被调用后没有 Toast，页面也没有错误提示。
- 建议：将未就绪、用户操作要求、策略限制、不支持及未知错误转换为简短的本地化反馈；正常系统关闭与卸载清理不弹错误。失败后重新从 `document.pictureInPictureElement` 同步实际状态。

### A2 · 优先：播放地址存在即允许进入，缺少媒体就绪判断

- 位置：`PlayerPage.vue:2228`、`:3448`。
- 按钮仅通过 `playbackSrc` 禁用，处理函数也不检查 `readyState`、视频轨道可用性或 `disablePictureInPicture`。
- 组件探针确认 `readyState === HAVE_NOTHING` 时按钮仍启用并请求 PiP；真实 API 此时可能拒绝请求，现有 A1 又会隐藏错误。
- 建议：区分“支持 PiP”“可以进入”和“当前已在 PiP”。进入须满足媒体就绪条件；已进入时应允许退出，不能因媒体临时缓冲而禁用退出。按钮与 P 快捷键使用同一准入条件，通过元数据及源变化事件更新。

### A3 · 优先：未决请求可被重复触发，长按 P 会反复切换

- 位置：`PlayerPage.vue:2136`、`:2226`。
- 没有进入/退出请求中的状态或互斥保护；`KeyP` 分支未过滤 `e.repeat`。
- 组件探针保持首个请求未决，连续两次点击及一次 `repeat: true` 的 P 键事件产生了三次 API 调用，按钮仍启用。
- 建议：增加请求中的状态，防止按钮和快捷键重入；P 键忽略自动重复。请求结束后同步浏览器实际状态，并避免迟到请求更新已卸载或已换片的播放实例。短请求也应防重入，耗时较长时显示局部忙碌反馈。
- 这确认了重复请求行为；真实浏览器是否拒绝、合并或表现为闪烁，仍需平台验收。

### A4 · 产品扩展：离开播放页就关闭小窗

- 位置：`src/layouts/AppShell.vue:1034`、`PlayerPage.vue:1372`、`:403`、`src/lib/player-media-source.ts`。
- 路由内容按当前组件挂载；播放器卸载会暂停视频、移除媒体源、退出该视频的 PiP、销毁 HLS 并释放会话。
- `use-active-playback-session.ts` 保存的是续播入口快照，没有持有视频或后台播放实例。
- 组件探针确认卸载后视频源被清除，暂停与退出 PiP 被调用。
- 当前实现支持停留播放页时切换到其它应用观看小窗；导航到资料库等其它页面会中断播放。这是当前生命周期的明确边界，与历史“回到刚才播放页”的设计一致，不应当作退出清理错误。
- 若目标是边浏览资料库边看，建议在应用壳层持有单一活动播放实例，让路由页面承载播放器界面和操作入口。video、HLS、会话清理、进度、观看时长与播放列表都需由该实例统一负责；回到播放页复用原实例。仅把当前大组件放进 KeepAlive 不足以完整解决单实例、换片、后台快捷键与资源退出策略。
- 必须覆盖停止播放、锁定应用、切换服务器、真正退出、新影片接管、自动下一集和异常恢复，防止双重播放或旧服务器会话残留。

## 后续体验与性能候选

| 候选 | 代码依据与建议 | 验证边界 |
| --- | --- | --- |
| 主播放面的状态提示 | 当前 PiP 仅改变按钮的 ARIA 状态，按钮没有不同的活动视觉样式。可增加“正在小窗播放”和“返回主画面”操作，保持暂停、音量、进度等操作可用 | 原生 PiP 的尺寸、外观和系统按钮受浏览器控制；主页面提示不等于能定制系统窗口 |
| Media Session | `src/`、`electron/` 无 `mediaSession` 接入。可逐步接入影片信息、播放/暂停和 seek，改善系统媒体控制 | 各平台显示哪些控件需实测；HLS 的 seek/position 必须使用全片绝对时间并进入现有换会话逻辑，不能直接把全片秒数赋给偏移流的 `video.currentTime` |
| 触屏入口 | PiP 按钮为 `size-9`，即通常 36×36 CSS px，没有额外命中区。触屏应扩大至至少 44×44，并保持底栏空间 | 桌面鼠标场景可保留紧凑视觉；需检查触屏布局，不在本轮宣称完成缩放验收 |
| 平台能力适配 | 当前只检测标准 `pictureInPictureEnabled` 和 `requestPictureInPicture`。只有 WebKit presentation-mode 能力的环境不会显示此入口 | 先建立目标浏览器/桌面能力矩阵，再决定是否增加 WebKit 适配。不能据此断言全部 Safari 不可用 |
| 后台工作减量 | 当前有 250ms 播放时钟校正、HLS 每秒状态轮询和帧率跟踪。小窗播放时主页面可能不需要相同频率的展示性更新 | 这是候选而非已测性能缺陷。HLS 轮询还参与失效恢复和 seek 决策，帧回调也参与逐帧能力；应先区分健康检查与展示工作，测量后降频，保留进度/观看时长与恢复能力 |

## 建议实施顺序与验收

1. 局部可靠性改进：A1–A3，集中封装 PiP 支持、准入、请求中状态、事件同步和清理；补充持久回归测试。
2. 局部体验改进：活动状态、返回主画面、触屏命中区；按目标平台逐步接入 Media Session。
3. 若产品要求跨页面持续小窗播放，再单独实施 A4 的应用级播放实例，避免与入口修复混成一次架构变更。
4. 真机验收：direct/HLS、播放/暂停、长按 P、系统关闭小窗、全屏与 PiP 切换、后台/最小化、换片及自动下一集、服务器切换和应用锁定。依平台记录支持与降级行为。
5. 有性能诉求时采样主窗口可见与隐藏、小窗开启与关闭时的网络请求、主线程更新、丢帧和 CPU，再决定降频范围。
