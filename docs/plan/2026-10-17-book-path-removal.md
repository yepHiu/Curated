# 漫画与写真移除目录后的内容显示修复

## 问题与行为

旧实现删除存储目录后，外键只将 library_path_id 置空，列表仍返回这些作品；Web 服务也没有使已加载的列表失效。现场无任何存储目录，却仍显示 8 本漫画和 22 本写真。

移除目录后，其下不再受其他目录覆盖的作品退出列表、搜索和详情访问。保留磁盘文件、作品 ID、标题覆盖、AI 资料、收藏、评分、标签、备注及进度；重新添加目录并扫描相同位置时恢复原记录。重叠目录使用仍有效的最深层目录重新关联。

## 实现

- 迁移 0070 为两库增加 detached 标记，并在同一迁移事务中检查旧的无目录关联记录：仍被现有目录覆盖的重新绑定，否则标记为脱离目录。不删除作品或文件。
- 删除目录及重新绑定/标记脱离在同一事务内执行；列表/搜索和详情排除 detached。扫描 upsert 保持原 ID 与用户资料并清除该标记；已移除目录的迟到扫描无法越过外键约束重新挂回。
- Web 删除成功后清空旧列表并重新加载，刷新失败保留空缓存和可重试错误状态。旧列表分页响应、旧详情响应通过请求序号/目录变更版本检查，不能重新插入已移除的作品。
- API 路径与 library-config.cfg 不变，需更新前端及 Server。Mock 演示数据未纳入此次真实存储目录修复。

## 验证

- 存储测试覆盖漫画/写真移除、重叠目录保留、相似前缀隔离、最后目录移除、迟到扫描拒绝、重扫身份/资料恢复、磁盘原文件不变及旧数据库迁移。
- Web 服务两个文件共 27 项测试通过，新增晚返回列表防回填及刷新失败缓存清理验证；lint、类型检查与 Web API 生产构建通过。
- 已保存开发数据库快照，重编译并重启开发后端。真实列表接口均返回 total=0；数据库分别保留 8/22 条脱离目录的作品。

- 扩展回归中 storage/server/comicscanner/photoscanner 包通过；app 包的影片扫描集成用例 `TestIntegration_RunScan_FilenameSamples` 在临时素材下载文件清理时发生 Windows 文件占用错误（两个 organize 子项），因此本次不能宣称 app 全包通过。该影片测试未在本次修复中修改。
