# Agent 用量展示优化建议

日期：2026-10-16。状态：标题调整已实施；其余为讨论建议，尚未实施。

## 当前展示与问题

SettingsAISection 的用量卡片目前包括时间、渠道、状态筛选，八项同级指标，最近运行和工具审计。总 Token、输入输出 Token、调用用量覆盖率、失败/部分完成/取消、首字耗时与总耗时混排，难以快速判断消耗及异常。最近运行在窄屏隐藏大部分辅助信息。

## 用户目标与展示顺序（讨论修订）

用户确认两个目标：首先清晰直观地了解用量；遇到问题或想深入了解时能找到相关内容。此前“四张摘要卡”建议撤回，避免让速度、失败和用量再次成为同级重点。内容层次优先通过阅读顺序、字号、留白和就近展开表达，避免新增嵌套卡片和反复分割。用户所说的“这个东西”未指明具体控件，当前按减少容器式分割理解，实施前应结合实际页面确认。

1. 默认视图先回答“选定时间内用了多少”：紧邻时间范围显示 Token 总量，辅以输入/输出拆分及任务次数。明确 Token 是模型处理文本的计量单位；缺失用量就近标注“部分用量未返回”，完整统计时不突出技术性覆盖率。
2. 接着回答“用在哪里”：近期使用记录默认展示时间、用户可理解的任务类型、Token 与状态。任务名称仅在已有可靠信息时使用，不能根据模型名或错误码编造。先保留简单记录，再评估渠道分布及趋势。
3. 记录支持点开查看详情：模型、输入/输出 Token、耗时、模型调用次数、工具执行记录。有失败时提供可理解的原因及有依据的下一步操作；原始错误码位于进一步展开的技术详情中。
4. 失败时在汇总附近出现轻量提示，例如“有 2 次任务未完成 · 查看”，进入相关记录。没有异常时不长期占用主视图。失败、部分完成、取消与等待用户操作应明确区分，不能统称失败。
5. 平均速度与完整工具审计不作为默认主指标；在记录详情或按需展开的统计详情中可访问。已有独立审计入口应保留，不能因运行关联字段不足而丢失记录。
6. 时间选择保持明显；渠道和状态筛选在使用记录附近按需提供。汇总和记录的筛选范围必须清楚，实施前核对后端实际行为。

## 后续可选增强

- 按天 Token 趋势，输入/输出堆叠；同时提供渠道分布，回答“何时消耗、消耗在哪里”。
- 明确区分用户任务次数与模型调用次数，一个 Agent 任务可能调用模型多次。
- 多模型使用量对比以及失败原因聚合，有足够数据后再做。
- 暂不直接显示费用；需要准确模型定价、缓存 Token 等计费字段及价格维护机制，现有 Token 数据无法可靠代表账单。

## 数据边界

现有 AISummary 提供 runs、failed、partial、cancelled、modelCalls、usageCalls、toolCalls、输入/输出/总 Token 和平均首字/总耗时。不能直接推导完整成功率，因为状态还包括等待输入、等待确认等；应增加明确完成计数或定义终态分母。

第一阶段的层级、标签、布局调整可复用现有汇总。运行与工具审计的关联能力、可读错误原因需先核对现有实现，缺少数据时再定义接口补充。按天趋势、渠道分布、多模型聚合应由后端对筛选范围内的完整数据提供聚合，不能用当前分页的最近运行冒充全量趋势。现有报告范围还受记录保留期限影响。
