# 设置页滚动条视觉建议（2026-09-25）

## 现状

设置页有两个独立滚动区域：桌面侧栏 `nav` 和右侧内容区 `SETTINGS_SCROLL_ROOT_ID`。它们都沿用 `src/style.css` 的全局 8px 滚动条：浅灰/白色半透明轨道和灰色手柄；内容区另设 `scrollbar-gutter: stable`，切换分区时减少宽度跳动。窄屏侧栏变为原生选择器，主要滚动发生在内容区。

## 推荐：轻量悬浮轨道

只给设置页的两个滚动区域使用局部样式，不改全站滚动条。

- **轨道**：透明或极低对比度，不画出一整条明显的槽。右侧内容边缘留少量间距，让手柄不贴住卡片。
- **手柄**：桌面约 7–8px，胶囊圆角，常态使用低对比的中性色；悬停或拖动时增加对比度，并带少量主题色。常态仍可辨识，避免完全隐藏。
- **侧栏**：同一视觉语言，但手柄可略细、颜色更淡；滚动条位于侧栏边缘，不压住导航文字或 Beta 徽标。
- **状态**：键盘聚焦滚动区域时保持可见；在高对比度/强制颜色模式下交给系统滚动条。不要为滚动条加发光、持续动画或自动消失逻辑。
- **布局**：保留内容区现有 `scrollbar-gutter: stable`，避免分区切换时卡片宽度变化；窄屏沿用系统原生滚动体验。

## 备选风格

| 方向 | 效果 | 取舍 |
| --- | --- | --- |
| 推荐：中性常态、主题色交互 | 与当前深色卡片和粉色主题协调，位置清楚 | 需要局部覆盖全局滚动条样式 |
| 完全主题色手柄 | 品牌感最强 | 长内容页会形成一条持续吸睛的粉色竖线 |
| 自动隐藏浮层 | 内容区最干净 | 鼠标、触控板和键盘下不易发现当前位置；自绘行为成本高 |

## 实现边界与验收

优先使用 CSS 原生滚动条伪元素及 `scrollbar-color`，不引入自绘滚动容器或 JavaScript。Firefox 对滚动条宽度的控制比 Chromium 粗，验收以可用性和颜色层级为准，不追求像素完全一致。检查深/浅主题、桌面长设置分区、较矮窗口中的侧栏滚动、375px 窄屏、键盘滚动，以及强制颜色模式。若做视觉微调，局部样式可以挂在内容区 ID 和侧栏专用类上。
