# AI 标签整理的大影片库可靠性

**后续需求更新**：本文件保留第一轮诊断和当时验证结果；累计 160 项冻结方案已由[标签复用、入口与历史](2026-10-02-tag-organization-entry-and-history.md)取代。当前累计词汇不设 160 上限，单次最多 12 项，普通用户标签进入分页复用候选。当前 1,200/10,000 用例验证增长到 240 项并分析完整范围，测试名称已改为 `VocabularyGrowthAndRestart`。下面的“冻结”描述仅代表第一轮历史实现。

## 问题定位

本次依据代码和隔离测试定位，未读取或修改用户实际资料库、未调用付费模型。

- 全库入口分页调用完整影片列表再逐条建立任务，启动成本随影片数量扩大，并受 HTTP 请求取消影响。
- 词汇逐页增加，但合并后超过 160 项就报冲突；重试从同一页继续，可能再次失败。
- 分类固定每批 5 部；长资料超出输入预算，或单部返回错误证据，会使整批失败。
- 模型临时超时、限流及服务故障没有自动重试；分类阶段持续故障仍会遍历余下全库并记为失败。
- 部分数据库错误直接返回、部分检查点错误被忽略，可能留下 running 状态且 worker 等待下一次唤醒。

## 实施范围

1. 全库任务在 SQLite 事务中直接固定活跃影片 ID，避免逐页加载完整 DTO。
2. 词汇达到 160 项上限、或缩小到单片后归纳输入仍超预算时冻结现有词汇，继续分类；剩余容量不足时有界接纳新增项，保留已有规范词汇。
3. 分类遇到输入/输出预算或批次校验问题时缩小影片批次；单片仍因词汇过长超预算时再对词汇分页，各页先校验证据再合并，保留最多 12 个不重复匹配，单部失败不牵连其他影片。
4. 临时 Provider 故障最多尝试三次，等待可取消；持续故障暂停任务、保留待处理项，支持手动重试。
5. 检查点失败明确进入 blocked；取消、关闭服务和成功结果不被迟到状态覆盖。

不新增 API、配置项或数据迁移。保留用户标签权限、来源证据验证、NFO 只读和逐片事务。

## 测试安排

- 10,000 部合成影片：全库快照、重复请求幂等、后续新增影片不进入既有任务。
- 至少 1,200 部完整假 Provider 流程：多批词汇增长至上限、分类中断及恢复、检查点不重复写入。
- 10,000 部完整假 Provider 流程作为显式压力测试；与 1,200 部使用相同断言，日常 CI 默认运行 1,200 部。
- 长摘要与低上下文窗口：分类批次自动缩小，真实证据保持完整。
- 429/503、网络中断与超时分类：有限重试、持续故障保留 pending、取消等待。
- 非法证据、词汇冲突、数据库检查点失败：失败范围与终态正确。
- 既有 600 部整理/撤销、人工冲突保护、取消恢复及后端回归。

命令均在 backend 目录执行，使用默认 Go 缓存。真实模型的语义质量、付费配额和端到端耗时不由合成测试代表。

## 复现证据

使用 Go overlay 载入 `64260b85` 中修复前的 worker，不替换工作区文件；仅将旧请求函数改名，以兼容新增的测试编译。

| 用例 | 修复前结果 | 修复后结果 |
|---|---|---|
| 1,200 部，每批增加 12 个词汇 | 第 14 页超过 160，停在 vocabularyProcessed=650，processed=0，`AI_ORGANIZATION_VOCABULARY_CONFLICT` | 160 个词汇冻结后继续分类，40 部成功后模拟关闭，恢复完成 1,200 部 |
| 11 部，各 4,000 个汉字摘要，32K 窗口 | 10 部失败，仅最后 1 部成功 | 自动缩小批次，11 部成功；发给分类模型的完整摘要不截断 |
| 11 部，其中一部返回伪造证据 | 5 部失败，6 部成功 | 仅错误影片失败，另 10 部成功 |

词汇上限是有意保留的产品约束：达到上限即停止扩展，并不表示分析过后面的全部原始资料。`vocabularyProcessed` 保留实际归纳数量（本测试为 700），`vocabularyReady` 表示可以进入分类；最终 `processed` / `succeeded` 仍覆盖整个任务。无法匹配现有词汇的影片保持 unresolved，不凭空添加标签。

## 可重复执行命令

在 `backend/` 运行日常回归：

```powershell
go test ./internal/app ./internal/storage -run 'TestTagOrganization|TestTopic|TestRetryableTopicRequest|TestCreateAllTagOrganization' -count=1 -v
```

10,000 部端到端压力测试（只生成临时 SQLite 库与合成数据，只访问本机 httptest Provider）：

```powershell
$env:CURATED_TAG_SCALE_TEST = '1'
go test ./internal/app -run '^TestTagOrganization10000VocabularyGrowthAndRestart$' -count=1 -v
Remove-Item Env:CURATED_TAG_SCALE_TEST
```

测试把写额度设为 10,000/分钟以避免消耗真实等待时间；另有 1 次/分钟额度的取消测试，验证 waiting_quota 与取消后的不再写入。压力测试耗时不能作为实际模型或默认写额度下的完成时间预测。

全量回归额外发现 Windows checkout 的 CRLF 导致新迁移的 TXT 提示词哈希不一致；独立修复在模板渲染前统一内置资源换行，不改源数据、不改提示词规范版本，原有哈希断言已经通过。
