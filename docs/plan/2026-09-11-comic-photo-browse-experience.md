# 漫画库 / 写真库浏览体验优化建议

日期：2026-09-11
状态：implementing
关联：性能切片见 `docs/plan/2026-09-11-comic-photo-library-performance.md`；已落地 UI 对齐见 `docs/plan/2026-09-11-book-library-ui-preview.md`（verified，REQ-0049）。本文件跟踪浏览体验优化：工具栏方案 A 与阅读页沉浸 HUD 正在落地。

## 设计框

| 项 | 决策 |
| --- | --- |
| 产品面 | 浏览面。用户任务是扫封面、找到一册、续读/续看、做最低限度整理。 |
| 先例 | 影片墙：海报优先、紧凑、整卡可点、工具栏短标签。详情预览批次已按 REQ-0049 对齐。 |
| 层次 | 先封面墙，其次继续阅读/浏览，再次标签与收藏。不要把设置式筛选或首页推荐轨搬过来。 |
| 状态 | 加载骨架、空库、无搜索结果、加载失败重试、Beta 关闭重定向、窄屏 375px 已有。缺的是「能力未实现却仍画出入口」的状态。 |
| 系统影响 | 多数是漫画/写真独立服务与页面；不要抽共享 `VirtualMovieMasonry`，不要让 Agent 触及这两个库。 |

## 现状（相对影片墙）

视觉节奏已经接近：右对齐工具栏、网格滚动槽、卡片边框、未开始不画进度条。能力上漫画是可管理的书库，写真仍是可浏览的 ZIP 墙。

```
找得到          扫得过           续得上           理得顺
  │               │               │               │
  ▼               ▼               ▼               ▼
壳层自由文本    全量 DOM 墙     漫画有进度 API   漫画：批量/编辑/删除
标签点进去      写真默认可截断   写真进度是空壳   写真：只能加标签
= 子串 q=       进页必 reload    无「正在读」集合  卡片无星标
favorite/read   名含 Virtual     阅读器无 ±1 预取  排序「收藏优先」
已写未接线      尚未分块窗口                      对写真几乎无意义
```

明确不抄影片的部分：刮削、演员、Saved Views 全家桶、推荐、Insights、Agent。书库筛选维度少，先接线已有字段，不先做书签系统。

## 工具栏：当前不优雅的原因

REQ-0049 把漫画/写真工具栏做成影片 `LibrarySavedViewsControls` 的外形（右对齐胶囊按钮、`gap-1.5`、共用「排序」文案），但没有带上影片那一套的职责分工。测试还明确断言墙上不再出现 `filterUnread` / `filterReading` / `filterRead`。结果是：**看起来像影片墙，做的事却只剩计数 + 排序 +（漫画）批量。**

```
影片墙（浏览）
  [筛选 chips →]  筛选  排序  书签  批量
  进入批量时：整簇换成 全选可见 / 退出；底栏才是动作

漫画墙（现在）
  共 N 册   [搜索 chip]  排序  批量
  进入批量时：计数、搜索 chip、排序都还在，再加 全选 / 退出
  底栏 ComicBatchActionBar 再次提供 全选 / 退出

写真墙（现在）
  共 N 册   [搜索 chip]  排序（含无效的「收藏优先」）
```

具体别扭点：

1. **排序里塞了筛选。** 「收藏优先」不是顺序，是把收藏提前；漫画文案里已有 `filterFavorite` / `filterReading`，`filterComics()` 也能按收藏和阅读状态过滤，页面却只传 `q`。`ComicsView` 改 query 时还在清一个已经没有 UI 的 `filter` 字段。
2. **控件职责混在一起。** 搜索在壳层，工具栏又用一颗 secondary 按钮当「当前搜索」；空结果 Card 再放一次「清空搜索」。影片用 chip 行表达所有约束，书库只有搜索这一种 chip，标签/收藏/在读进不来。
3. **批量没有换成选择态。** 影片进入批量会拿掉筛选/排序/书签，避免和选择抢位置。漫画顶栏继续排序，同时又和底栏重复「全选当前可见」「退出批量」。
4. **两库强行同一套菜单。** `BookLibraryToolbar` 写死三档排序。写真不能收藏，菜单里仍有「收藏优先」；漫画能管理，却没有筛选入口。
5. **默认排序按钮只写「排序」。** 与影片相同：未改排序时看不出当前是导入时间。书库选项更少，更适合按钮上始终显示当前值，例如「导入时间」。
6. **左计数、右一串按钮、整体 wrap。** 窄屏时计数、chip、排序、批量折成两行，没有影片 chip 行那种横向滑。批量时更挤。

## 建议的工具栏信息架构

原则：一个控件只做一件事；浏览态和批量态互斥；不画不能用的入口；外形可以像影片，职责按书库来。

```
浏览态（漫画）
  共 128 册     [在读 ×] [作者:甲 ×] [雨 ×]     筛选    导入时间 ▾    批量

浏览态（写真，能力未齐前）
  共 40 册      [标签 chip / 搜索 chip]         导入时间 ▾

批量态（仅漫画）
  已选 6 / 128                                 全选可见     退出
  底栏只留动作：收藏 / 取消收藏 / 标签 / 删除
  不再重复全选与退出
```

| 控件 | 做什么 | 不做什么 |
| --- | --- | --- |
| 计数 | 当前墙上可见册数 | 不承担筛选 |
| Chip 行 | 当前约束，一点清除：`q`、精确 `tag`、收藏、阅读状态 | 不再用单独一颗「搜索按钮」冒充筛选 |
| 筛选 | 子集：全部/收藏、未读/在读/已读；标签可后置进同一菜单 | 不做成影片那种播放状态+评分+分辨率大面板，不做书签 |
| 排序 | 只排序：导入时间、文件名、最近阅读 | 不再把「收藏」放进排序 |
| 批量 | 进入选择态；顶栏只保留选择摘要和退出 | 浏览控件在批量时隐藏 |

筛选入口两种做法，推荐 **A**：

- **A. 一颗「筛选」胶囊 + 短菜单 + chip。** 和影片工具栏家族一致，窄屏不占一整行分段。菜单里只有书库真有的两三项。
- **B. 全部 / 收藏 / 在读 / 已读 分段。** 更直接，文案也已经写在 `comics.filter*`。缺点是和右侧重排，375px 很容易把墙顶挤矮；写真也不该出现阅读状态分段。

排序按钮始终显示当前值（「导入时间」），选中项用 Check，不要默认空白成「排序」。写真在能收藏之前不要出现收藏排序或收藏筛选。

搜索继续走壳层，不搬回页面输入框。工具栏 chip 只是把壳层的 `q` 投影到墙旁边，和影片 filter chips 一样。

## 建议分层

### 0. 先停掉会骗人的界面

这些不是新功能，是浏览可信度。

1. **写真列表完整性**  
   Web 适配器只拉一页，默认约 100 本后静默丢册。库越大，「墙上看不见」越像产品缺陷。对应性能方案切片 A。

2. **写真进度条与「继续浏览」**  
   `PhotoBook.currentPageIndex` / 卡片进度 / 详情继续文案都在，但没有 progress API，查看器也不写回。未开始时已改为不画进度条；一旦有非零页码，用户会以为能续看。两条路二选一：补有界进度写入，或在进度 API 落地前不要展示续看页码。

3. **详情点标签 ≠ 精确标签筛选**  
   `ComicDetailView` / `PhotoDetailView` 把标签写成 `query: { q }`，墙面再做标题/文件名/路径/标签的子串匹配。点 `作者:甲` 会误伤标题里碰巧含这些字的册。应走精确 `tag=`（漫画 `filterComics` 和写真后端列表已有 tag 口径可接）。

4. **写真「按收藏排序」**  
   排序菜单有收藏优先，但写真没有改收藏的 UI，字段默认也用不上。入口应在能改收藏之后再出现，或暂时从写真菜单拿掉。

### 1. 扫墙：性能方案 A–B 就是浏览体验

几百本时，卡顿和封面请求风暴比缺一个筛选按钮更伤「海报优先」。

- 写真分页循环到 `total`；进页 `ensureLoaded`，扫描/导入/监听终态仍强制 reload。
- `VirtualComicGrid` / `VirtualPhotoGrid` 做成与影片墙同构的 `DynamicScroller` 分块窗口；封面 `loading` / `fetchpriority` 按块策略，默认仍 lazy。
- 墙面保持统一 `358/537` 封面框 + `object-cover`。详情预览已经按自然比例排；墙上混排宽高会变慢、难扫，不作为浏览优化。
- 滚动位置恢复默认不做；若做，复用影片 `use-library-scroll-preserve` 语义，不要另起一套。

后端 tags 批量查询、ZIP `OpenPage` 直开、漫画 cache 按 `maxBytes` 淘汰、阅读器 ±1 预取见性能方案 C/D，对墙面感知次之，可后置。

### 2. 找得到：接线已有过滤，不先做 Saved Views

`filterComics` 已支持 `favorite` 与 `readStatus`，`ComicsView` 却只传 `q`。写真后端列表支持 `tag` / `favorite`，前端 params 更窄。优先页面内短入口：

| 入口 | 作用 | 为什么先做这个 |
| --- | --- | --- |
| 精确 `tag=` | 详情标签、卡片标签可点回墙 | 用户已经在点，只是语义错了 |
| 收藏 | 只要收藏的册 | 漫画已有批量收藏；卡片缺星标 |
| 阅读状态 | 未读 / 在读 / 已读 | 漫画已有 `readStatus`，墙面没入口 |
| 排序补一档 | `lastReadAt` / `lastViewedAt` | 比「文件名」更像继续阅读 |

壳层搜索保持自由文本，不必上影片那种番号/演员联想。作者、系列继续用标签，不新开元数据模型。

不要在这一层做完整 Saved Views。影片书签要持久化 mode、多维筛选和排序；书库目前三维都未接线，先让 query 可分享、可返回即可。

### 3. 续得上：闭环，而不是首页轨

漫画详情「继续到第 n 页」是对的。缺的是从墙面回到这本书：

- 漫画：阅读状态筛选或「最近阅读」排序，足够代替首页「继续观看」轨。Beta 书库不要进 Home 推荐。
- 写真：没有写回就没有继续。若做进度，应对齐漫画的有界 pageIndex + `lastViewedAt`，查看器节流保存；偏好可以仍用全局 `photoViewer`，不必第一期做成每书偏好。
- 阅读器/查看器：当前页 ±1 原图预取（性能方案 D）。翻页卡顿会被感知成浏览差，即使墙已经很快。

卡片单击进详情、封面在详情里从第 0 页打开，保持影片式「先看再进」。写真卡片双击进查看器可以保留，但不要再加第三种手势。漫画卡片已声明 `toggleFavorite` / `openReader` 却没有星标或双击，不要只在类型上对称。

### 阅读页：画面优先，控件分层

对照画布：工作区 `canvases/book-reader-chrome.canvas.tsx`。

播放器路由铺满内容区。`comic-reader` / `photo-viewer` 仍走 AppShell 普通内边距，顶栏继续放返回、添加媒体和主题。底栏 `ComicReaderChrome` 把上一页、页码、下一页、模式切换、拼上页、拼下页排成一串；模式图标表示即将切换到的模式。`fit` / `direction` 有每本偏好，阅读页没有入口。`ComicReaderSettingsMenu` 只渲染原始枚举，阅读器未挂载。写真查看器没有拼页（对），但切换模式不写回。

```
现在
  顶栏 [返回详情] … [添加媒体]
  侧栏 |  内边距里的画面
       |  [<] 12/80 [>] | 模式 | 拼上页 拼下页

建议
  铺满内容区（与播放器同级）
  叠层顶：[返回] 标题
  画面：翻页模式左右热区
  叠层底：细进度  [<] 12/80 [>]  [设置]
  设置：模式 / 适配 / 方向；漫画翻页才出现拼页
```

点击画面隐藏控件这一行为保留。不把播放器的播放列表、截图搬进阅读器。不改成长卷虚拟列表。

### 4. 理得顺：补写真最小管理，漫画补墙上的收藏

漫画已有编辑、删除、定位源文件、批量收藏/标签/删除。墙上仍不能一键收藏，收藏只能进编辑框或批量模式，扫描效率低。

写真故意隐藏了未实现的管理动作，这是对的；结果是整理只能靠外部改 ZIP 再扫描。建议最小集，仍然独立服务、独立表：

1. 收藏（让「按收藏排序」成立）
2. 评分或继续只读，二选一，不要只展示不能改的星
3. 删除或至少 reveal 源归档
4. 需要时再批量；不要为对齐而先做批量条

标签点击走精确筛选后，多标签 AND 可以后置。Agent、Insights、跨库搜索不做。

## 建议切片顺序

工具栏信息架构可以先做，不依赖虚拟化。写真列表截断仍是正确性，可并行。

| 顺序 | 切片 | 用户可感知结果 | 依赖 |
| --- | --- | --- | --- |
| 1 | 工具栏职责拆开：排序只排序、批量换成选择态、去掉空壳收藏排序 | 顶栏好用，批量不再和排序挤在一起 | 仅前端 |
| 2 | 漫画筛选入口 + chip 行（收藏 / 阅读状态 / `q`）；精确 `tag=` | 能找到在读和标签，点标签不再变成子串 | 前端为主 |
| 3 | 写真全量列表 + 进页短路 | 超过 100 本仍看得到 | 性能 A |
| 4 | 停掉空壳续看 / 或补写真进度 | 进度条只代表真进度 | 产品二选一 |
| 5 | 真虚拟化墙 | 几百本可扫 | 性能 B |
| 6 | 漫画卡片星标；写真最小管理后再给写真筛选/批量 | 墙上能整理 | 与 5 可并行 |
| 7 | 阅读页铺满内容区 + 精简 HUD（设置收纳模式/适配/方向/拼页） | 阅读像播放器一样画面优先 | 仅前端 |
| 8 | 最近阅读排序；阅读器 ±1 预取；漫画 cache 淘汰 | 续读更快 | 性能 D |

## 明确不做（本建议范围）

- 不改影片墙实现，不把两库网格抽成与影片共用的组件作为前置。
- 不把搜索搬回页面内（继续壳层搜索）。
- 不上 Agent / 推荐 / Insights / 刮削 / OCR。
- 不做全书长卷虚拟列表、详情页元数据分页 API。
- 不把写真持久磁盘 cache 当作浏览体验的前置（`photoCache.maxBytes` 仍为预留）。
- 墙面不改成按原图比例的瀑布流。
- 不把影片 Saved Views / 大筛选面板整套搬到书库工具栏。
- 不把壳层搜索搬回页面内输入框。

## 开放问题

1. 筛选入口：已按 **A 一颗「筛选」胶囊 + 短菜单 + chip** 落地。
2. 批量顶栏：已换成选择态；底栏去掉重复的全选/退出，保留清空选择与动作。
3. 写真继续浏览：先补进度 API，还是先从 UI 拿掉续看页码？
4. 收藏入口：漫画是否要在卡片上放影片同款星标，还是只靠工具栏「仅收藏」+ 批量？
5. 写真最小管理做到哪一步算 Beta 可日常用：仅收藏，还是必须含删除/reveal？
6. 阅读页：已按播放器同级铺满内容区，隐藏壳层顶栏，叠层返回 + 精简 HUD。

## 当前落地（2026-09-11）

- 漫画墙：`q` / 精确 `tag=` / 收藏 / 阅读状态经 URL 可分享；旧 `sort=favorite` 迁移为收藏筛选。排序只剩导入时间与文件名，按钮显示当前值。
- 写真墙：精确 `tag=` 与排序；无收藏/阅读状态入口。壳层搜索只改 `q`。
- 详情点标签走 `tag=`，不再写成子串 `q=`。
- 阅读器/查看器路由铺满内容区并隐藏壳层顶栏；叠层返回与标题；底栏进度 + 翻页 + 设置；漫画翻页模式可拼页；翻页模式左右热区；写真偏好写回全局 `photoViewer`。
- 阅读设置菜单以整条底栏卡片为锚点向上打开，与工具栏外缘保持 8px 间距，不再覆盖 HUD。

未写入 PRD 前，本文只是建议，不表示已批准排期。
