# 多分片影片兼容与 FC2 独立展示

日期：2026-10-04
状态：proposed（用户目标已明确；分片与番号的对应关系待确认，尚未进入实现）
关联需求：REQ-0056、REQ-0057

## 1. 用户目标与范围

本轮用户提出：少量影片有第 1、2 部，FC2 常见第 1、2、3、4 部，需要兼容多部/分片；现有「影片」入口继续保留，另增「FC2」入口，FC2 不再与其他影片混排；两者共用存储池、标签等资源。

这里将用户所说的「影片」「FC2」标签理解为导航入口名称；元数据标签、用户标签仍是共用的描述与筛选资源。FC2 归类应由作品编号决定，不依赖可随意删除的用户标签。

这是现有成人资料库的功能扩展。合规化仍由独立项目推进，本仓库的合规化暂停决定继续有效，见 [此前决定](2026-07-18-curated-compliance-and-metadata-source-decoupling.md#当前决定本仓库暂缓2026-10-04)。

当前唯一需要确认的产品语义：用户说的第 1、2、3、4 部，是同一番号对应多个文件，还是不同番号的系列续作，或两者都有。这会决定分片是否共用一条作品记录；不能按标题相似直接合并不同作品。

## 2. 已核对的代码事实

| 位置 | 当前实现 | 对需求的影响 |
| --- | --- | --- |
| `src/domain/movie/types.ts`、`backend/internal/contracts/contracts.go` | 每个 Movie 只有一个 `location`，没有有序视频文件列表 | 需要作品到视频文件的一对多关系 |
| `backend/internal/storage/migrations/0001_init.sql` | `movies.code` 和 `movies.location` 都唯一 | 同一番号不能靠复制 movies 行表达多个分片 |
| `backend/internal/storage/scan_repository.go` | 扫描相同番号的另一条路径时，更新原作品的 `location` | 旧分片路径会被新分片替代，而不是被追加 |
| `backend/internal/library/organize.go` | 自动整理目标为 `{number}/{number}{ext}`，目标存在时报冲突 | 多分片需要保留分片标识，避免整理到同一目标文件 |
| `backend/internal/storage/movie_stream.go` | 播放文件从作品唯一 `location` 解析，并验证资料库根目录 | 分片播放也必须经过相同路径校验 |
| `backend/internal/storage/playback_curated.go` | 播放进度按 `movie_id` 保存 | 第二片进度会覆盖第一片，必须增加文件维度 |
| `src/router/index.ts`、`src/components/jav-library/AppSidebar.vue` | 主影片页与入口存在，FC2 没有独立入口 | 可以复用现有海报墙、详情和播放器，而增加独立浏览范围 |
| `src/lib/homepage-portal.ts` | 仅首页 hero 排除 FC2，最近导入、继续观看及推荐仍可能包括 FC2 | 若要求不混排，不能只改侧栏或 hero |
| `src/lib/movie-number.ts`、`backend/internal/scanner/number.go` | 已识别多种 FC2 编号格式 | 可复用编号归一化，但需补充分片后缀及边界覆盖 |

上述为本轮阅读事实，不表示新的 FC2 分区或多分片能力已经实现。

## 3. 展示结构

建议在现有侧栏「影片」旁新增永久显示的「FC2」入口，不增加实验开关或启用向导。

| 浏览入口 | 默认展示 | 使用的基础能力 |
| --- | --- | --- |
| 影片 | 非 FC2 作品；包含单文件与多分片作品 | 现有海报墙、排序、筛选、收藏、详情、批量管理 |
| FC2 | FC2 作品；包含单文件与多分片作品 | 复用相同组件与服务，仅限定作品分类 |

分类应统一处理 `FC2-1234567`、`FC2-PPV-1234567`、`FC2PPV-1234567` 等现有格式。已有 FC2 自动出现在新入口，无需移动文件、创建另一存储池或重新添加作品。

不混排需要覆盖影片首页栏目、主影片列表、FC2 列表及其搜索、筛选、分页、计数、相关推荐。从 FC2 进入详情、播放或点击标签后，返回与继续浏览仍保留 FC2 范围；保存筛选、滚动位置及播放列表也要保留这一范围。

存储管理、标签管理等共用管理页继续使用同一套资源。收藏、历史等涉及两类作品的共用入口应支持按「影片 / FC2」查看，避免在用户查看其中一类时混入另一类；具体入口位置在 UI 实现时沿用现有页面结构。

这里的分离是浏览分类，不是权限分区。直接打开 FC2 详情仍是正常的资料库访问。

## 4. 共用资源

保留同一 Server、SQLite 数据库、资料库根目录与存储池，不要求把 FC2 文件搬到另一个物理目录。

元数据标签、用户标签、演员信息、收藏与评分能力、备注、导入任务、刮削调度、备份和播放器共用。用户在同一磁盘目录混放两类作品时，也应能按编号分别展示。

FC2 分类与标签独立：删除一个名为「FC2」的用户标签不能把作品移回「影片」；普通作品也不能因为手动添加该标签就被错误归类。浏览筛选命中各自范围内的作品，标签词表仍共用。

## 5. 多部与多分片的两种关系

| 情况 | 示例 | 建议处理 |
| --- | --- | --- |
| 同一番号的有序分片 | `FC2-1234567-CD1.mp4`、`FC2-1234567-CD2.mp4` | 一条作品记录，下挂多个有序视频文件 |
| 不同番号的系列续作 | `ABC-001` 为第一部，`ABC-002` 为第二部 | 保留两条作品；如用户也需要，可另建系列关系与顺序 |
| 同一番号的不同版本 | 完整版、剪辑版、不同清晰度或重复拷贝 | 不能仅凭番号相同就当成第 1、2 片 |

多分片能力同时适用于非 FC2 和 FC2；FC2 只是更常见的使用场景。

## 6. 建议的数据结构与交互

### 6.1 作品与文件分开

作品记录继续承载番号、标题、封面、演员、标签、评分、收藏和备注。拟增加视频文件记录，表达 `Movie → VideoFile[]`；文件具有稳定 ID、所属作品、路径、分片序号、媒体时长及探测信息。

作品列表按作品计数：一部作品有四个分片时，只展示一张海报，并标明「4 个分片」。详情中按序号展示「第 1 片」「第 2 片」等可播放项；单文件影片继续保持现有操作体验。

现有 `location` 可在兼容阶段保留为默认播放文件投影，不能继续作为全部视频文件的唯一事实源。列表 DTO 提供分片数量，详情 DTO 提供有序文件列表；客户端通过服务合约访问这些能力。

### 6.2 扫描与导入

扫描分别识别作品番号和分片标识，优先支持明确的 `CD1/CD2`、`part1/part2` 等格式，按数字自然排序，保证第 2 片在第 10 片之前。具体要支持的实际文件命名需结合用户确认的关系确定。

同一路径重复扫描保持幂等。同番号、明确不同分片时追加文件记录；不能再覆盖另一分片路径。同番号但无法判断是分片还是版本时保留冲突信息，允许用户指定归属与顺序，不按标题、文件大小或扫描先后猜测。

导入查重需要区分「整部作品已存在」「此分片已存在」「同作品的新增分片」，避免把合法的追加分片都提示为重复影片。自动整理保留分片名称，例如 `{number}/{number}-CD1.mp4`，并沿用文件冲突保护。

### 6.3 播放、续播与萃取帧

播放请求应明确选择作品下的视频文件；服务端校验该文件确实属于作品，且位于允许的资料库根目录。直连、HLS、外部播放器和错误恢复都必须使用选定文件，不能回退到其他分片。

播放进度以文件 ID 保存。继续观看同时记录作品和最后播放的分片，重新打开可恢复「第 3 片、12:34」；每片进度互不覆盖。播放器支持分片选择及顺序播放，切换时正确释放上一片 HLS，会话取消或迟到响应不能覆盖当前片。

截图、高清帧、片段导出和帧标记必须保存文件 ID 与片内时间，否则不同分片的同一时间戳会对应到错误视频。共享的观看历史和时长可按作品汇总，底层仍保留实际文件归属。

## 7. 旧库兼容与管理操作

数据库升级为已有作品的当前 `location` 建立一个文件记录，保持作品 ID、收藏、评分、标签和备注不变。旧进度绑定到该路径对应的文件，不能默认猜成「第 1 片」；旧路径可能已经是曾被覆盖的第 2、3、4 片。

对于以前因扫描替换而未保留的其他分片，若源文件还在磁盘上，可在升级后的重扫中重新发现。不能声称仅靠迁移就能恢复数据库里已经丢失的路径。

回收站、恢复、永久删除、目录迁移/重绑定、健康检查、备份和还原必须覆盖所有关联文件。文件离线时保留其记录和分片顺序，显示不可用状态；一片缺失不应把整部作品当成完全缺失。操作默认沿用现有删除权限与确认规则。

## 8. 独立实施单元

1. **FC2 展示分离（REQ-0056）。** 建立统一编号分类，增加入口和浏览范围，完善首页、筛选、导航与计数；继续共用存储和标签。
2. **多分片扫描与存储（REQ-0057）。** 确认番号关系后增加文件模型和迁移，修复扫描覆盖，兼容整理与导入查重。
3. **多分片播放与管理（REQ-0057）。** 选择分片、文件级续播、顺序播放、萃取帧/导出及所有管理操作闭环，完成旧库回归后再标记需求已实现。

不同番号的系列关系仅在用户确认需要时纳入；不能用它替代同番号的多文件支持。

## 9. 关键验收

- 原「影片」入口没有 FC2；FC2 入口只显示 FC2，已有作品自动正确归类，刷新和重启后结果一致。
- 搜索、标签/演员筛选、相关推荐、收藏范围、分页总数与实际浏览分类一致；详情和播放返回原分类。
- 共用存储池中的两类文件无需搬迁，标签修改仍使用同一词表；用户标签不改变内建分类。
- 同一作品第 1、2、3、4 片全部保留且排序正确，重扫不增加重复项，不覆盖旧路径；非 FC2 同样适用。
- 第 2、10 片按数字排序；重复版本、序号冲突和缺失分片不会被静默猜测或覆盖。
- 每片能独立播放与续播，切换、HLS 恢复、外部播放器和后台播放均保持选定文件。
- 从后续分片截取/导出时使用正确源文件和时间；旧单文件截图与播放不回归。
- 升级保留原作品 ID 和用户数据，旧进度归到原文件；删除、恢复、迁移、备份/还原覆盖全部分片。
- Web API 与 Mock 的交互和三语文案一致；相关后端测试、前端测试、类型检查和构建通过后再记录实现证据。
